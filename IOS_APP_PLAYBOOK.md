# iOS app playbook

A reusable guide for building iOS apps with paid AI features, subscriptions and one-time purchases. The aim is apps that are reliable, follow Apple's rules, keep users and the developer safe, and cost little to run. Started 7 October 2026 alongside [the Nifty Outfit Nook build plan](SWIFT_BUILD_PLAN.md). Nifty Outfit Nook is the first app built with it, and building that app is how this playbook gets written.

## How to use this playbook

- **[SECURITY_STANDARD.md](SECURITY_STANDARD.md) is required** for every app built with this playbook. It isn't optional and isn't a later phase.
- Each chapter starts with **Do this**, the short rules. The lessons under it give the reason and the evidence, one bullet each.
- The tag at the end of a lesson says where it was learned, such as "(Phase 11)" or "(Stage A)". Look in the build plan's progress log for that phase if you need the full story.
- Unless a lesson says otherwise, it was checked with Xcode 26.6, Swift 6.3, the iOS 26.5 simulator (build 23F77) on an Apple-silicon Mac and GitHub's hosted `macos-26` runner, between 13 and 17 October 2026.
- Only write down what was actually done and checked. Put a new lesson in the chapter it's about, not at the end. If it replaces an older lesson, edit or remove the old one. Keep a one-line "Superseded:" note only where the old advice is a tempting trap. Lessons that only apply to Nifty Outfit Nook stay in the build plan's progress log.

## 1. Repositories and repo hardening

**Do this**
- Keep separate repos for design and planning, the app, and the private backend. Use Git Flow in the app and backend repos (`main`, `develop`, `feature/*`, `release/*`, `hotfix/*`) with protected branches and required CI. The model is in [SWIFT_BUILD_PLAN.md](SWIFT_BUILD_PLAN.md#repositories-and-branching).
- Merge CI first, then add the ruleset. Test the ruleset by trying to break it.
- Merge with a script that waits for checks and calls the REST merge endpoint.
- Promote `develop` to `main` through a `promote/...` branch built with `git commit-tree`.
- Set the repo's security settings with `gh api` and list them in the README.
- Install a gitleaks pre-commit hook in every clone.

**Lessons**
- **CI first, rulesets second.** Merge the PR that adds CI, then create the ruleset, so the required checks already exist by name. A required check is the job's `name`. Pin it to GitHub Actions with `integration_id: 15368` so a commit status from elsewhere can't satisfy it. (Phase 1b)
- **One ruleset can cover `main` and `develop`** (`refs/heads/main` and `refs/heads/develop` in `include`). With `bypass_actors: []` the API reports `current_user_can_bypass: "never"`, administrators included. Rules used: `deletion`, `non_fast_forward`, `required_linear_history`, `required_signatures`, `pull_request` (0 approvals for a one-person repo, `allowed_merge_methods: ["squash"]`) and `required_status_checks`. (Phase 1b)
- **Test the ruleset from a throwaway clone.** `git commit --allow-empty` on `develop` and push: GitHub rejects it and lists every rule broken. Deleting the branch is rejected too. `gh api repos/{o}/{r}/rulesets/rule-suites` shows each evaluation afterwards. (Phase 1b)
- **`gh pr merge` refuses under `required_signatures` when your commits are unsigned.** GraphQL reports the PR as `BLOCKED` even with every check green. `gh api -X PUT repos/{o}/{r}/pulls/<n>/merge -f merge_method=squash` merges it as a normal user: GitHub signs the squash commit and the ruleset still applies. Wrap it in a script that runs `gh pr checks <n> --watch` first. Signing commits locally probably also fixes it; not tried. (Phase 1b)
- **Squash-only promotions to `main` need a promotion branch.** With linear history and squash as the only method, each promotion leaves `main` with a squash commit `develop` never gets, so the two stop sharing history. The first promotion merged only because `main` was still the first commit; `git merge-tree --write-tree origin/main <next develop commit>` showed the next one would conflict. A sync PR back into `develop` is squashed too, so it doesn't help. What works: `git commit-tree <develop's tree> -p origin/main`, push it as `promote/...` and open the PR from there. The diff is exactly what changed since the last promotion. Script it and point the agent notes at the script. (Phase 3)
- **Rebase a stacked branch after a squash merge with `--onto`.** Once the branch underneath is squash-merged, its commits no longer exist on `develop`. Fetch, then `git rebase --onto origin/develop <old base sha>` replays only your own commits. (Stage A audit)
- **Repo settings that aren't files**, all set with `gh api`: squash merge only and delete branches on merge (`PATCH /repos/{o}/{r}`); secret scanning and push protection (`security_and_analysis` in the same PATCH; non-provider patterns and validity checks stay off on a free personal repo); `PUT .../vulnerability-alerts`, `.../automated-security-fixes` and `.../private-vulnerability-reporting`; a read-only workflow token that can't approve PRs (`PUT .../actions/permissions/workflow`); only GitHub-owned actions with SHA pinning enforced (`PUT .../actions/permissions` with `allowed_actions=selected` and `sha_pinning_required=true`, then `.../selected-actions` with `github_owned_allowed=true`); and approval for every outside contributor's workflow run (`PUT .../actions/permissions/fork-pr-contributor-approval` with `all_external_contributors`). Nobody will find these in the code, so list them in the README. (Phase 1b)
- **Local secret hook.** `.githooks/pre-commit` runs `gitleaks git --pre-commit --staged --redact --log-level warn`; a script sets `core.hooksPath` per clone. Test it with a fake but well-formed token (a random 36-character `ghp_` string trips `github-pat`). AWS's documented example key is allowlisted, so it proves nothing. (Phase 1b)

## 2. Project setup

**Do this**
- Hand-write the project file with synchronized folders and xcconfig files. Add local packages as folder references.
- Run package tests and UI tests from one test plan in the app scheme.
- Treat warnings as errors in the xcconfig and `Package.swift`, never on the command line.
- Commit both `Package.resolved` files and build with `-onlyUsePackageVersionsFromResolvedFile`.
- Add new String Catalog keys from the build's `.stringsdata`, in Xcode's own JSON format.

**Lessons**
- **A hand-written project file works.** With `objectVersion = 77`, each source folder is one `PBXFileSystemSynchronizedRootGroup` listed in the target's `fileSystemSynchronizedGroups`, and the Sources and Resources build phases stay empty. Build settings go in xcconfig files (`baseConfigurationReference`). Check with `xcodebuild -list` and a real build. (Phase 1a)
- **Add a local package as a folder reference, not an `XCLocalSwiftPackageReference`.** Use a `PBXFileReference` with `lastKnownFileType = wrapper` and `path = Packages/<Name>`, and product dependencies without a `package` field. With `XCLocalSwiftPackageReference`, Xcode built the package with `-suppress-warnings` and silently left its test targets out of the scheme and test plan. (Phase 1a)
- **Run package tests through a test plan.** Each package test target is listed as `{"containerPath": "container:Packages/<Name>", "identifier": "<TestTarget>", "name": "<TestTarget>"}`. The scheme then runs package and UI tests together on a simulator, which matters when the package is iOS-only and `swift test` can't run on the Mac. (Phase 1a)
- **Warnings as errors:** `SWIFT_TREAT_WARNINGS_AS_ERRORS = YES` in the project xcconfig and `.treatAllWarnings(as: .error)` (Swift 6.2 tools) in `Package.swift`. On the `xcodebuild` command line it reaches package targets too and can clash with `-suppress-warnings`. Prove it works with a deliberate warning. (Phase 1a)
- **A test-only package still resolves its whole manifest.** swift-snapshot-testing pins swift-custom-dump, xctest-dynamic-overlay and swift-syntax in `Package.resolved` though the `SnapshotTesting` product builds none of them; list them in the dependency note. With a local package added as a folder, Xcode writes its own `Package.resolved` under `*.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/`. Commit both, check they agree, and build with `-onlyUsePackageVersionsFromResolvedFile`. (Phase 2b)
- **A lower module's debug catalog can take pages from a higher one.** The design system's catalog takes `extraPages: [Page]` (an id, a title and an `AnyView`), and the app target passes in pages that draw feature models. The design system stays free of models. (Phase 9)
- **Take new String Catalog keys from the build.** A command-line `xcodebuild` doesn't add new strings to a package's catalog. With `-emit-localized-strings` on (it is for Swift packages in Xcode 26), each file leaves a `<File>.stringsdata` JSON in `DerivedData/.../<Target>.build/Objects-normal/<arch>/` with every `String(localized:)` key exactly as the catalog wants it (`%lld`, `%@`, positional forms) and its comment. A script that adds the missing ones found all 120 new keys of a phase. Write the file with Python's `json.dumps(catalog, indent=2, separators=(',', ' : '), ensure_ascii=False, sort_keys=True)` plus a final newline, which matches Xcode byte for byte and keeps diffs clean. Plural variations ("1 piece", "17 pieces") still go in by hand; test a count of one. (Phases 4, 7a, 13)
  - Superseded: finding the keys with a regex over `String(localized:)` calls. Use the build's keys instead. (Phase 7a)
- **Don't add files to the worktree while `xcodebuild test-without-building` runs.** With synchronized folders the package reloads and the run hangs. Write scratch files outside the repo, or wait for the run to end. (Stage A audit)

## 3. CI on GitHub Actions

**Do this**
- Check the runner image README, select Xcode by path and pick the simulator at run time.
- Pin every action by SHA. Least-privilege token, `persist-credentials: false`, a timeout per job, cancel superseded PR runs.
- Keep the required check's name on a small aggregator job with `if: always()`.
- Build once on one runner and run tests from the `.xctestrun` on others. Build with a UI-only test plan for the UI jobs.
- Split UI tests by class with a catch-all part, and balance the parts from the test log.
- Let docs-only PRs skip the heavy jobs.
- Read step times and runner load before changing anything. Measure two or three runs before believing a change.
- Remember the free plan: five macOS runners at once, shared with every other run in the account.

**Lessons**
- **Check the runner image before picking a label.** `images/macos/macos-26-arm64-Readme.md` in `actions/runner-images` lists each Xcode and simulator runtime (`macos-26` had Xcode 26.0.1 to 26.6 and iOS 26.2, 26.4 and 26.5). Select Xcode with `sudo xcode-select --switch /Applications/Xcode_26.6.app` and choose the simulator from `xcrun simctl list devices available --json`, because names and runtimes differ from a dev Mac. (Phase 1b)
- **Moving to a new Xcode major (Xcode 26.6 to 27.1, 19 to 20 October 2026), verified on the app.** The hosted `macos-26` image stops at 26.6; Xcode 27.1 is on the `xcode-27` label (`runs-on: xcode-27`, `/Applications/Xcode_27.1.app`, a link to `Xcode_27.1_Release_Candidate.app`) and that image has only the iOS 27.0 simulator runtime, so tests and snapshot references move to 27.0 too. Expect: `nonisolated` needed on extensions of nonisolated types and on `Shape` structs under default main actor isolation; two new swift-format config keys; SwiftPM 6.4 swapping `xctest-dynamic-overlay` for `swift-issue-reporting` in both `Package.resolved` files; a `Task { () async throws(E) in }` closure sometimes returning the wrong error, which crashed or failed tests (return the error as a value instead); iOS 27 reading a control before its card in an overlay (set `accessibilitySortPriority`); and the AX5 audit reporting element-less clipped text on a few screens. Snapshots that load images can render a few points different from run to run, and a UI test runner can fail to bootstrap on a cold simulator; a rerun cleared both. (nifty-outfit-nook PR 59)
- **Pin actions by SHA.** `gh api repos/<owner>/<repo>/git/ref/tags/<tag>` gives the commit SHA when `object.type` is `commit`; an annotated tag returns `tag`, and its `object.url` leads to the commit. Write `uses: actions/checkout@<sha> # v7.0.1` so Dependabot can still update it. (Phase 1b)
- **gitleaks without a third-party action:** download the release tarball, check it against a SHA-256 from the release's checksums file kept in the workflow, and run `gitleaks git --redact .` after a `fetch-depth: 0` checkout. About 7 seconds on `ubuntu-latest`. (Phase 1b)
- **Workflow defaults:** top-level `permissions: contents: read`, `persist-credentials: false` on checkout, a timeout on each job, a concurrency group that cancels superseded runs only for pull requests (`cancel-in-progress: ${{ github.event_name == 'pull_request' }}`), and the `.xcresult` uploaded only `if: failure()`. (Phase 1b)
- **Keep the required check's name with an aggregator job.** Give the parallel jobs new names and make the required one (`build-and-test`) a small `ubuntu-latest` job with `needs:` on all of them, `if: always()`, and a step that fails unless every `needs.<job>.result` is `success`. Without `always()` it's skipped when a job fails, and GitHub counts a skipped required check as passed. The ruleset doesn't change. (Phase 5b)
- **Read the step times before changing anything.** An 18-minute job was 1.7 minutes of Release build, 1 of Debug build, 1 of simulator boot, 2 of package tests and 10 of UI tests one after another. The UI tests were the thing to split. (Phase 5b)
- **Measure the runner before blaming the tests.** A background step printing `sysctl vm.loadavg`, `memory_pressure -Q`, `vm_stat` and the top processes every 15 s found load averages of 200 to 560 on 3 cores while the simulator ran, about 3 GB compressed, the app at 65 % CPU, `diagnosticd` at 25 %, and a new simulator starting widget extensions, Spotlight and News in its first minutes. Single XCUITest queries took 9 to 55 seconds then. (Stage A)
- **Each UI job costs about 6 minutes before its first test passes**: setup, a cold simulator boot and the first app launch (that first test alone took 2 to 3 minutes). More parts give less back each time. Booting the simulator in the background on the same runner during the build made the build take 9 minutes instead of 1 to 2.5. (Phase 5b)
- **Build once, boot while it builds, test on other runners.** Test jobs start with the build job and boot their simulator in the background (`xcrun simctl boot <udid> &`). The build job runs `build-for-testing`, tars the products (an artifact zip drops file permissions) and uploads them. The test jobs poll this run's artifacts (`gh api repos/{o}/{r}/actions/runs/$GITHUB_RUN_ID/artifacts?name=<name>`, with `actions: read`), download with `actions/download-artifact` (v8 checks the digest) and run `xcodebuild test-without-building -xctestrun <file>`. The `.xctestrun` uses `__TESTROOT__` paths, so it works from another folder on another runner, and the iPhone simulator build ran the iPad tests too. The build comes off four of five runners; the 5-minute boot now decides when testing starts. Treat a failed API call while polling as "not yet" (a TLS timeout once read as an upload). If the build job is still queued after a few minutes, build in the test job, since the test jobs may hold the runners it needs. (Stage A)
- **`-only-testing` doesn't make `build-for-testing` build less; a second test plan does.** A `UITests.xctestplan` with only the UI test target, passed as `-testPlan UITests`, built in 58 s instead of 113 s locally and 1.8 to 2.1 minutes instead of 2.6 to 3.1 on CI, because the package test targets weren't built. Test with the same plan. (Stage A)
- **`-only-testing` for a Swift Testing function needs its parentheses.** `-only-testing:Target/Suite/function` ran nothing and passed quietly; `-only-testing:"Target/Suite/function()"` ran the test. A whole suite (`Target/Suite`) works without. (Phase 21c)
- **Split UI tests by class with a catch-all part.** `xcodebuild test-without-building -only-testing:UITests -skip-testing:UITests/ClassA -skip-testing:UITests/ClassB` runs every other class, so a new class can't be left out. Pass the selection through the test script. (Phase 5b)
- **Balance the parts from the test log.** Each `Test Case '-[Class test]' passed (N seconds)` line gives a class's time. Summing them per part showed one part held 22 of 38 minutes; regrouping into four parts of about equal time took the check from about 29 to 20 minutes with no new runners. The same class swung by up to two times between runs, so record the numbers in the workflow and rebalance when one part drifts. (Phase 12b)
- **Spare time on a non-UI job isn't free UI time.** A UI class run after the package tests on the same runner still needed 3 to 7 minutes for its first launch and made that job the longest. Give iPad tests a part of their own. (Phase 15b)
  - Superseded: adding the iPad UI tests as a second step in the lightest UI job. It cost 12 minutes for 6 minutes of tests. (Phase 15a)
- **Retry UI tests once, on CI only, for simulator launch failures.** "Timed out while launching application via Xcode" and "Failed to get launch progress" lost a test twice in about 25 runs, and no wait inside a test catches them. `-retry-tests-on-failure -test-iterations 2` works with `test-without-building`; a test that fails twice still fails the job. Keep it out of local runs and package tests, and say in the workflow why it's there. (Phase 11)
- **Parallel testing on simulator clones doesn't pay on the free runner.** With `-parallel-testing-enabled YES -parallel-testing-worker-count 2` on `macos-26` (3 CPUs, 7.5 GB), three parts that took 21 to 27 minutes hit the 40-minute timeout, and one clone was still being set up 23 minutes in. (Stage A)
- **Boot a newly created simulator before its first test run.** Twice, `xcodebuild test` on a simulator just made with `simctl create` sat for 20 minutes with an empty log. `xcrun simctl boot <udid>`, then `xcrun simctl bootstatus <udid> -b`, then the run, worked first time. (Phase 11)
- **An unsigned device archive is a cheap Release check.** `xcodebuild archive -destination generic/platform=iOS CODE_SIGNING_ALLOWED=NO` plus its checks took 1.9 to 3.2 minutes, less than the simulator Release build it replaced, and it checks the binary that ships. Run it before any simulator starts on that runner; after the iPad tests it took 5.7 minutes. See chapter 14 for the checks. (Stage A)
- **Docs-only pull requests can skip the heavy jobs without a third-party action.** A small `ubuntu-latest` job checks out with `fetch-depth: 0`, lists `git diff --name-only "$BASE...$HEAD"` (the PR's base and head SHAs) and outputs whether anything other than docs changed. Count Markdown inside source folders as code, since a synchronized folder can put it in the app. The heavy jobs run `if: needs.changes.outputs.code == 'true'`; the aggregator passes when they were skipped for that reason and fails if `changes` failed. (Stage A)
- **No `pull_request` run appears while the PR has a merge conflict.** Two pushes started nothing until `gh pr view <n> --json mergeable` showed `CONFLICTING`. Rebase and push again. (Stage A)
- **Other runs share your five macOS runners.** With a second PR's CI going, jobs waited 10 to 37 minutes. With six macOS jobs in one run, `swift-format` once sat queued for 14 minutes behind the test jobs. Compare job and step times, not the run's wall time, when measuring a CI change. (Phase 15b, Stage A)
- **Where it ended.** The required check went from 26 to 34 minutes to about 16, with no test retried. What's left is about 5 minutes of simulator boot per job and about 35 minutes of UI tests across five runners. Fewer app launches per test, or bigger runners, are the next levers. (Stage A)
- **A PR that went green on its own branch can break `develop`.** When another PR lands during the last CI run, the squash merge succeeds with no conflict and nobody builds the combined tree: 24c added a protocol requirement, and #78's two test stand-ins stopped compiling. Right before `scripts/merge-pr.sh`, run `git fetch` and `git log HEAD..origin/develop`; if it shows anything, merge it in and let CI run again. After a merge, build the new `develop` once. (Phase 26, 21 October 2026)

## 4. App structure, data flow and navigation

**Do this**
- Split the package into Models, Fixtures and Features. Only the app target builds concrete services.
- Stores keep data; pure functions decide. Every rule takes `now` and a `Calendar`.
- Put services in the environment with a fail-loudly default, not an optional.
- Number each screen load and drop any result that isn't the newest.
- Keep each screen in one place. Let the root own tab paths so other tabs can open screens there.
- Switch over route enums with no `default:`.
- Give the app one `-fixtures` launch argument for data sets and behaviours.

**Lessons**
- **Split the package three ways.** Models holds value types, rules as pure functions and service protocols, with Foundation only and no user-facing strings (enum cases are words; screens localize them). Fixtures holds actor stores and sample data and depends on Models. Features depends on Models only, and the app target is the one place that builds concrete services. (Phase 3)
- **Give environment services a fail-loudly default.** `@Entry` needs an explicit default for a non-optional type. A services value with a `.unavailable` default, whose members fail loudly when called, makes missing wiring show up at once. An optional (`NookServices?`) compiles but hides it. (Phase 3, Stage A audit)
- **Stores keep data; rules decide.** Stores return everything they hold and screens filter with pure functions (eligibility, repeat window, favourites, filters). Every rule takes `now` and a `Calendar`, tests pin a UTC Gregorian calendar and a fixed date, and fixture dates are generated relative to `now` so the running app reads naturally. (Phase 3)
- **Typed throws work across async protocols and actors.** `func garments() async throws(StoreError) -> [Garment]` in a protocol, implemented by an actor, compiles under complete strict concurrency. `Task.sleep` throws an untyped error, so catch it and throw your own `.cancelled`. Keep "couldn't finish" as a thrown error and "the data doesn't allow it" as an outcome, so a network failure can never look like a small closet. (Phase 3)
- **Screen loads overlap, so number them.** `.task`, a reload on return, Undo and Try again can all start loads that finish out of order. Bump a counter for each load, capture it, and drop any result that isn't the newest. Leaving or cancelling bumps it too and sets the state at once, so a service that ignores cancellation can't put a result on screen later. Prove it with a store wrapper whose next read waits until the test releases it: start two loads, release them in the wrong order, check only the newest shows. (Phase 10b, Stage A audit)
- **Route switches have no `default:`.** A `switch` over the route enum with every case listed fails to compile when a route is added, so a new route can't silently fall to a stub. (Stage A audit)
- **One launch argument for data set and behaviour.** `-fixtures demo:offline` (also `slow`, `stylist-fails`, `stylist-partial`, `stores-fail`, and options such as `demo:weather=snow:laundry=full`, in any order, unknown parts ignored) gives UI tests and by-eye checks every loading, error and visual state without new flags. (Phases 3, 5a)
- **A generated data set should own its arithmetic.** A SplitMix64 generator with its own `int(in:)` and `unit()` makes a 2,400-item data set identical on every run, without relying on how the standard library picks random integers. Draw per-record day offsets into a `Set` so dates are unique, and never generate an event before the record exists; test both. (Phase 3)
- **Seed anything that must never move with your own hash, not `Hasher`.** `Hasher` is seeded differently on every launch. FNV-1a over the ID's UTF-8 bytes, then SplitMix64, gives the same result every time; pin the generator's first number in a test so a change to the arithmetic fails loudly. (Phase 9)
- **Keep a generated layout a pure function and test every mix.** A layout that takes roles and a seed and returns frames in a fixed design box can be checked for all 1,708 mixes of 2 to 6 pieces from 7 kinds: every frame inside, no pair overlapping more than a set share, one placement each. That found odd cases no by-eye check would. Apply random nudges before the overlap checks, send failures to a nearest-first search for free space (offsets precomputed and sorted, stop at the first fit: 10 ms down to 0.1 ms), then scale the whole result to fit. Overlap shares don't change with scale, so the limit holds. (Phase 9)
- **Work out each cell's details once, when the data loads.** A small value per item with a dictionary by ID made the slowest filter on 2,400 items 7 ms in Debug, fine on the main actor. Build VoiceOver strings in the cell's body, so only cells on screen pay. (Phase 6)
- **Debounce search with a cancellable task, and give tests a way to wait.** Each keystroke cancels the last `Task { try? await Task.sleep(for: delay); guard !Task.isCancelled ... }`. A `settleSearch()` that awaits the pending task plus a counter of searches applied lets a test type four letters, settle, and see one search. Apply at once when the field is emptied or Search is pressed. (Phase 6)
- **Reuse a list screen's model with a scope.** An optional scope (IDs in order, a mark per item, a fixed kind) gave See all and a picker the same search, filters and grid as the main list. Filling it from data the opener already had meant the picker read nothing. (Phase 11)
- **Make a hand-changed record a new record.** A swap that kept the old ID would have shown a changed look as saved. A new ID per change, the old record kept for Undo, and a layout seed carried over from the first ID gave exact Undo with no store writes until Save. (Phase 11)
- **Point the child at the parent, and keep a copy of what it was made from.** A generated picture stores its look's ID plus the look's pieces and name at the time; the look stores nothing about its pictures. Nothing can disagree: deleting a picture never touches the look, a changed look shows as "earlier version" by comparing copies, and Undo of a delete relinks because the look returns with its ID. A pure `status(of:looks:)` covers it in unit tests. (Phase 12b)
- **Add a defaulted associated value to keep an enum change small.** `case suitcase(name: String, icon: SuitcaseIcon = .rolling)` let every existing `.suitcase(name:)` compile unchanged. (Phase 13)
- **Put drafts behind a protocol before there's storage.** A `DraftStore` with an in-memory actor let the draft flow be built and tested first. The form writes half a second after the last change (cancellable, with `settleDraft()` and a write counter for tests) and at once on any `scenePhase` other than `.active`, so nothing depends on a termination callback. Saving a draft with no changes removes it. (Phase 7b)
- **Make number entry forgiving and its error honest.** Accept the region's decimal mark and a point, trim spaces, reject signs, letters and a second mark, and treat an empty box as "no value", never zero. Round the accepted range inwards to whole numbers in the user's units for the error line, and test that both shown ends save. (Phase 14a)
- **Date new demo records older than the ones tests list.** Adding six sample looks and pictures to the demo set dated three to five months back left the newest looks, the Home shelf and the first pictures as they were, so the tests that expect an exact list kept passing. A newer date would have reshuffled every list test. (Sample wardrobe, PR #56)
- **Take a generated record's attributes from the asset you attach.** The 2,400-piece closet picked colours at random and then the nearest photo by kind; with only 51 photos, about nine in ten pieces had a photo that contradicted their name and colour chips, and searching "green" found a white top. Pick the photo first and copy its colours into the record and its name; keep random values only for records with no photo. Draw the random values as before, so nothing else in the set moves. (Real-photo audit fixes)

**Navigation**
- **Keep each screen in one place and open it from other tabs through the root.** The root owns a tab's path (`@State var savedPath: [Destination]`, handed to that tab's `NavigationStack(path:)`) and puts an "open in Closet" action in the environment. Another tab sets the path, then the selection; Back lands on the list. Every screen exists once and its pushed screens work wherever the user started. UI tests check both the tab and the title. (Phases 12a, 13)
- **A path set for a tab that hasn't appeared yet doesn't fire `onChange(of: path)`.** Do the same check in `onAppear` as well. (Phase 12b)
- **Reload when a tab appears and when its path shrinks.** `.task` runs each time a tab appears, and `.onChange(of: path)` on a shorter path picks up changes made on pushed screens. A pushed detail's own `.task` also runs again when you come back to it, so it shows edits without a callback. (Phases 7a, 7b, 13)
- **Let a detail hand a removal back to the list that pushed it.** The detail returns a small value (which item, what was done, how to undo) through a closure; the list pops, reloads and shows the toast with Undo, so the toast lives on a screen that stays. (Phase 7a)
- **Keep Undo for a delete somewhere that lasts.** A toast with Undo plus a quiet line over the list with the same Undo, kept until the user leaves the tab, is kinder than a 6-second toast and reachable by a slow UI test. (Phase 12a)
- **A screen pushed from more than one tab can push its own next screen.** `.navigationDestination(item:)` inside it works in whichever stack it's in; ways out that belong to the parent come in as closures. Test both routes. (Phase 10a)
- **Hiding the back button stops the swipe back too.** With `.navigationBarBackButtonHidden(true)` and your own Cancel, neither an edge swipe nor a mid-screen swipe leaves the form on iOS 26, so unsaved work can only be left through Cancel and its question. (Phase 7b)

## 5. Paid requests and cost control

These lessons come from building paid features against mocks, before any backend. The server-side half (ledger, limits, kill switch) belongs in chapter 15 once it's built.

**Do this**
- Build and check a paid request on the phone with a pure function before sending anything.
- Prove "opening sends nothing" and "this sends exactly one" with a counting test double.
- Drop late answers, and keep what's on screen when a retry fails.
- Offer an existing result before paying for a new one.

**Lessons**
- **Check a paid request with a pure builder, and test it against the next step.** A builder taking the closet, suitcases, preferences and the date returns blocking issues, warnings and the request, so re-checking on every tap is cheap. One test ran 2,688 combinations and checked that the send button is enabled exactly when a request is built and that every built request passes the context builder the service uses. Pair it with a few word-level tests on real fixtures: when a piece fails two rules, the screen must pick the reason the user would recognise. (Phase 10a)
- **Prove "opening sends nothing" with a counting stub.** Swapping the services bundle's stylist for a small counting actor let a unit test open the screen, change options, build the request and assert zero calls, with no UI test. (Phase 10a)
- **Count paid calls with a scripted actor.** A test service with a queue of replies (succeed, fail, wait until cancelled, or a hand-made outcome) and a call counter proved the rules that cost money: reopening sends nothing, switching versions sends nothing, Try a different outfit sends one, Retry sends one, failing stores send none. The same actor gives snapshot tests a "working" state. (Phase 10b)
- **Cancelling or failing keeps the result on screen.** A retry that fails offline leaves the earlier results with a banner over them, not an empty state. Late answers are dropped by the load counter in chapter 4. (Phase 10b)
- **Ask for something different by saying what was shown.** Passing the combinations already shown (`shownCombinations`) lets a deterministic mock give a new result on "Try a different outfit" and say honestly when nothing new is left, with no randomness in tests. (Phase 10b)
- **Rank on-phone suggestions with a pure function, then page through its list.** Ranking once and letting "Show 3 more" reveal more of the same list kept paging instant over 2,400 items and made "sends nothing" trivially true. (Phase 11)
- **Offer an existing result before paying for a new one, even in a mock.** Comparing a look's pieces with each picture's saved copy (ignoring order and IDs) lets the sheet open on "You already have a picture of this look", with Make another second. The reuse rule is built and tested before the real service exists. (Phase 12b)

- **Make a paid AI action a kept job with one key, not a screen's task** (27c, Nifty Outfit Nook, 22 October 2026). Keep the Idempotency-Key, the state and everything the request is built from in the local store; on launch and on each foreground, ask again with the same key for every job that was sent. A test that rebuilds the request from the decoded job and compares it with the original proves the body (and so the server's fingerprint) is the same. A job never sent and older than a few minutes should fail rather than send late.
- **A screen left open in the background isn't "looking at it".** The first notification checkpoint got no notification: the result's screen was still registered as showing when the app went to the background, so the job counted itself as seen. Check `isInForeground` before the on-screen rule, and let the screen mark it seen when she's back.
- **Use the completion-handler forms of `UNUserNotificationCenterDelegate`, on the main actor.** With the `async` `didReceive` form, tapping a notification on iOS 26.5 crashed the app in `UIApplication _performBlockAfterCATransactionCommitSynchronizes` (the completion ran off the main thread). A `@preconcurrency UNUserNotificationCenterDelegate` conformance with the completion-handler methods fixed it.
- **iOS gives a short, unpromised background task, not a polling loop.** `beginBackgroundTask` covered a 15-second fake answer on the simulator. Anything longer must be picked up at the next foreground or by push; `BGAppRefreshTask` runs when iOS chooses, and a store with `FileProtectionType.complete` can't be read while the phone is locked anyway.

## 6. SwiftUI layout and design systems

**Do this**
- Keep design tokens in one Swift file and test the asset catalog against it.
- Lay out illustrated scenes from the mockup's coordinates with pure, testable layout code.
- Reach for `ViewThatFits` and small custom `Layout`s before `GeometryReader` tricks.
- Check fills, toasts and bars by eye on the simulator; snapshots don't show bars.
- Keep `withAnimation` to the control that needs it.

**Design tokens**
- **Keep colour values in one Swift file and test the catalog against it.** A `Palette.swift` with every token's light and dark hex lets tests compute WCAG contrast without UIKit. One test decodes each `.colorset/Contents.json` (found through `#filePath`, readable from simulator tests and on CI) and compares it with the palette. Another resolves the compiled colour with `Color(name, bundle: .module).resolve(in: env)` for `.light` and `.dark` and compares linear sRGB channels (tolerance 0.004). Change one channel to prove both fail. (Phase 2a)
- **Xcode generates asset symbols for a package's catalog too.** A colour set named `background` gives the module `ColorResource.background`, so `Color(.background)` becomes ambiguous next to your own token. Label your initializer: `Color(token: .background)`. (Phase 2a)
- **Map text roles to Dynamic Type styles and test the default sizes.** `UIFont.preferredFont(forTextStyle:compatibleWith:)` at `.large` gives each style's default size, so a test can hold every role within a couple of points of the mockup. The smallest styles stop shrinking at 11 pt, so test growth upward only. (Phase 2a)
- **System font designs need no licence check.** `.rounded` (SF Pro Rounded) and `.serif` (New York) come with `Font.system(_:design:weight:)` and scale with Dynamic Type. (Phase 2a)
- **A colour close to the background disappears as a fill.** A soft accent (`#EFE6DB`) on the wall (`#F4EEE6`) passed every text-contrast test but made icon circles and pressed states invisible. Look at fills on the simulator. (Phase 2b)
- **A shadow that falls only below needs more than `.shadow`.** SwiftUI's shadow has no spread, so CSS like `0 10px 16px -12px` becomes a halo. Draw a background: the shape inset by the spread, offset down, blurred by half the CSS blur, masked with the shape punched out (`ZStack { Rectangle().padding(-n); shape.blendMode(.destinationOut) }.compositingGroup()`). It doesn't change layout. (Phase 2a)

**Illustrations**
- **Multi-colour vector art that follows dark mode: two SVGs per image set.** Give each `.imageset` an Any SVG and a Dark SVG (`"appearances": [{"appearance": "luminosity", "value": "dark"}]`) with `"preserves-vector-representation": true`. Generate both from one source with a script that maps every colour, and test that they differ only in colours and that each dark colour follows the rule. Clip paths, gradients and `opacity` rendered correctly from a package catalog. Replace `<use href>` with copies rather than trusting the system renderer. (Phase 4)
- **Keep hue where it carries meaning when recolouring art.** Mapping every blue to warm stone made sunny and cloudy windows look alike; keeping their blues at 40 % kept the weather readable. Things that stand for something real keep their colours and take the room's dimming in dark. Generate derived states (a faded "off") from the base drawing with the same script and test the shapes match. (Phase 5a)
- **Check derived art in dark on its own.** A faded "off" state put through the dark rule became the brightest thing on the dark floor. Give derived states their own dark rule and a test that they stay darker on average. A radial glow with a fixed end radius showed a hard edge once its frame shrank; set the radius from the frame. (Phase 5b)
- **Exporting art drawn by a mockup's JavaScript.** `new Function('window', 'document', source)(fakeWindow, {readyState: 'complete', querySelectorAll: () => []})` in Node ran the drawing script without a browser and returned its SVG strings. When one drawing is placed twice, rename its clip path IDs per copy. (Phase 6)
- **Lay out an illustrated scene from the mockup's own coordinates.** Keep every rect from the design's fixed stage (390 x 844) as data and compute one scale and origin per screen: fit what must show between the bars, never wider than the screen, never below the scale that keeps the tightest pair of controls 44 pt apart. Grow each tap area to 44 x 44. Pure layout code lets tests check every phone size for 44 pt targets, no overlaps and nothing under the bars. On a phone too short (iPhone SE), let the scene scroll rather than shrink targets. (Phase 4)
- **Switch whole layouts inside one screen, not between screens.** A small enum from `dynamicTypeSize.isAccessibilitySize` and `verticalSizeClass == .compact` picks which view the screen's `NavigationStack` shows. The model, the path and any sheet live in the screen, so rotating or changing text size keeps what's open. Give each control the same accessibility identifier in every layout. (Phase 5b)

**Measured bars and safe areas (iPhone, iOS 26)**
- **Inside `NavigationStack` in a `TabView`, inline title:** 116 pt top and 83 pt bottom on iPhone 17 and 17 Pro Max, 74 and 83 on iPhone SE (3rd generation). Put a full-bleed scene in a `ScrollView` with `.ignoresSafeArea()`, place content using those insets, and use `scrollDisabled` when it fits. (Phase 4)
- **iPhone 17 held sideways, navigation bar hidden:** 0 top, 62 pt each side, 64 pt bottom for the tab bar. A side column's `ScrollView` with `.contentMargins(.bottom, inset, for: .scrollContent)` keeps the last control above the floating tab bar. (Phase 5b)
- **A toast on a pushed scrolling screen can sit behind the floating tab bar.** A bottom overlay on a root `ScrollView` ends at the home indicator. Hang the toast on a clear layer, `.overlay { Color.clear.nookToast($toast) }`. (Phase 10b)

**Layout gotchas**
- **A shrinking `Text` next to a `Spacer` truncates instead of shrinking.** `minimumScaleFactor` plus `layoutPriority(1)` still gave "Clo…". `ViewThatFits(in: .horizontal)` over full, shorter and text-only versions, each with a `.fixedSize()` title, worked. (Phase 4)
- **A button label built with `ViewThatFits` can stack inside an `HStack`.** The row measured it narrowly first. `.fixedSize(horizontal: true, vertical: false)` on the button (below the accessibility sizes only) kept icon and words side by side. (Phase 7b)
- **Fill a screen between measured parts with a custom `Layout`.** A `Layout` that measures the top and bottom with a nil height and gives the rest to the middle does it in one pass, and `ImageRenderer` matches the screen. (Phase 17)
- **iOS 26 toolbars show a `Label` as its icon only**, even with `.titleAndIcon`. An `HStack` of image and text as the button's label shows both. (Phase 6)
- **On iOS 26 a confirmation dialog from a bar button hides its cancel button.** It shows as a popover with only the destructive choice. For "Discard your changes?", use `.alert` with destructive and cancel buttons. (Phase 7b)
- **`.task` never runs on a view with nothing in it.** An `if` that drew nothing while waiting for its photo had `.task(id:)` on the empty result, so the load never started. `ZStack { Color.clear; content }` under the modifier fixed it. Snapshot tests skip loading, so only the simulator showed it. (Phase 8b)
- **iOS 26 deprecates `SFSafariViewController.preferredControlTintColor`**, which fails a warnings-as-errors build. Leave Safari's controls alone. (Phase 14b)

**Overlays and coach marks**
- **Draw a coach-mark overlay above the whole tab app.** One observable tour controller above the `TabView` draws the overlay, so the dim covers the bars. Each target reports `frame(in: .global)` through `onGeometryChange`, keyed by an anchor ID and the view's own owner token (so a layout leaving doesn't remove the anchor the next layout just added). The spotlight then followed its target through rotation, window resizing, text sizes and scrolling with no extra code. (Phase 16a)
- **Measure before `.position`.** A view placed with `.frame(...).position(...)` fills its parent, so measure between `.frame` and `.position`. (Phase 16a)
- **Place a popover card in a custom `Layout`.** It measures the card (nil height), picks the side, and places spotlight, tail and card in one pass. Parts not shown go far off screen. (Phase 16a)
- **A soft cut-out in a dim:** draw the dim, then a blurred rounded rectangle with `.blendMode(.destinationOut)`, inside `.compositingGroup()`. (Phase 16a)
- **One modifier per screen decides when its coach mark may start.** `.screenTour(definition, isReady:)` asks the controller on appear, when `isReady` turns true, when another tour ends and on replay, via `.task(id:)` over those values. The controller owns the rules (never two at once, once a session, the tips switch), so 19 screens got tours without each knowing them. (Phase 16b)
- **Toolbar buttons can be targets.** `onGeometryChange` with `.frame(in: .global)` on a `ToolbarItem`'s button reported its window frame on iPhone and iPad. (Phase 16b)
- **Target a list's first item without changing the list.** Give the anchor modifier an `isEnabled` flag and apply it to every item with `isEnabled: item.id == items.first?.id`, so lazy grids keep their identity. (Phase 16b)
- **A sheet hides anything drawn behind it, coach marks included.** A tour overlay on the root view never showed over the Try it on sheet. The sheet draws its own tour layer from the same controller. (Stage A audit)
- **xcodebuild never adds new keys to a package's String Catalog.** Add each new key yourself (or from the build's `.stringsdata`), or the string ships untranslated with no warning. (Stage A audit)
- **A tour that scrolls a page puts the scroll position back when it ends,** or the title is left half under the back button. (Stage A QA)

## 7. Accessibility

**Do this**
- Record every screen at AX5 and look for hyphens that aren't in the words.
- At accessibility sizes, stack what sits side by side: icons above titles, Close above sheet titles, buttons before pictures.
- Test contrast on what's actually underneath, including see-through tints.
- Pass Reduce Motion and VoiceOver state in as parameters so tests can set them.
- Give each control the same identifier in every layout, and a short visible word plus a fuller spoken name where needed.

**Lessons**
- **Check contrast on what's actually under a see-through tint.** Blend the tint over each opaque colour it sits on (both ends of a gradient, the floor) before measuring, and list every pairing as data so a new pairing is one more line. (Phase 2a)
- **AX5 snapshots find layout bugs fast.** The first recording showed words broken mid-word in buttons, chips and rows. Fixes that held: `ViewThatFits` (icon beside a one-line title, else above a wrapping one), pairs of buttons that stack, and chip bars that wrap instead of scrolling. (Phase 2b)
- **At AX4 and AX5, move a row's icon above its words.** With a fixed icon column, "Occasion" broke as "Occa-sion" on a 402-point phone; AX3 still fit. Keep the icon column a fixed width so rows line up. A chevron column caused the same break ("measure-ments"); put the chevron on the icon's line and trim side padding at those sizes. A display-style screen title broke too; step it down one text style. (Phases 5b, 14a)
- **At AX5 a sheet's one-word title can break beside its Close button.** Put Close on its own line above the title at accessibility sizes. (Phase 10a)
- **On a welcome screen at large sizes, put the buttons before the picture.** At AX5 the title and text pushed Get started below the fold. Words, then buttons, then a small illustration keeps the action on the first screen. Give that stack `.fixedSize(horizontal: false, vertical: true)`, or a still image drawn at screen height squeezes it. (Phase 17)
- **Let a card's words scroll and keep its buttons.** `VStack { ViewThatFits(in: .vertical) { words; ScrollView { words } }; buttons.layoutPriority(1) }`. The still-image stand-in for the scroll view must be able to shrink (`.frame(minHeight: 0, maxHeight: .infinity, alignment: .top).clipped()`). (Phase 16a)
- **Fixed-size labels on art need a Dynamic Type cap until a large-text layout exists.** `.dynamicTypeSize(...DynamicTypeSize.xxxLarge)` on the scene kept labels inside their drawn spaces; accessibility sizes then get their own layout. (Phase 4)
- **Chip rows that wrap at AX5 can bury the content.** Twenty chips wrapped to several screens. Fold them behind "Show filters" at accessibility sizes only. (Phase 6)
- **Don't empty a vertical `TextField` in the `onChange` that strips its Return.** With `TextField(axis: .vertical)` as a one-line field, taking the line break out and then setting the text to "" in the same `onChange` left the field two lines tall, showing the prompt, and without focus, so the next words typed went nowhere (iOS 26.5 simulator, twice). Taking the line break out alone, as the other fields do, works; give "add another" an explicit button. (Phase 21c)
- **A text field's own prompt doesn't wrap.** With `TextField(axis: .vertical)` the prompt was still cut off at AX5. Give the field an empty prompt, draw the prompt as a wrapping `Text` behind it (hidden from VoiceOver, no hit testing), and set the field's `accessibilityLabel` to it. With `.isSearchField`, XCUITest finds it as `app.searchFields["…"]`. (Phase 6)
- **Keep drawings tappable in a cramped layout, with real controls beside them.** Hide the drawings from VoiceOver and put the same actions next to them as labelled 44 pt tiles, so nothing is read twice. A short visible word with a longer spoken name gets `accessibilityInputLabels([short, full])` so Voice Control answers to both. (Phase 5b)
- **Reduce Motion and VoiceOver can't be set in a test, so pass them in.** `\.accessibilityReduceMotion` and `\.accessibilityVoiceOverEnabled` are get-only, so `.environment(...)` doesn't compile. An animated view takes `animates: Bool` (false under Reduce Motion or a snapshot flag) and draws a fixed frame; when true, a `TimelineView(.animation(minimumInterval: 1.0 / 15))` drives a pure `drift(at:)` that unit tests can check. Screens that show these settings take optional overrides only tests pass. (Phases 5a, 14b)
- **Spoken units come from `Measurement.formatted`.** `.measurement(width: .wide, usage: .asProvided, numberFormatStyle: .number.precision(.fractionLength(0...1)))` gives "27.5 inches" for `accessibilityValue`; `.abbreviated` gives "27.5 in" for the screen. Pass the locale in so tests can pin it. (Phase 14a)
- **Accessibility order followed drawing order, not `accessibilitySortPriority`.** In an overlay, an invisible button over the target came before the card whatever the priorities. Drawing the button after the card (`.zIndex(2)` over `.zIndex(1)`, which works in a custom `Layout`) fixed it. (Phase 16a)
- **Check accessibility order from `debugDescription`, not a query.** XCUITest queries return elements breadth first; the printed tree is in the order the app exposes. A view with `.accessibilityAddTraits(.isModal)` shows there as an `Alert`. `.accessibilityHidden(true)` on a `TabView` didn't remove screens from XCUITest's tree, so test "nothing under the overlay" with `isHittable`. (Phase 16a)
- **Escape can't be tested from XCUITest on the iPhone or iPad simulator.** `app.typeKey(XCUIKeyboardKey.escape, modifierFlags: [])` reached neither `.keyboardShortcut(.cancelAction)` nor `.onKeyPress(.escape)`. Route Escape and the VoiceOver escape action to the function Skip calls, unit-test that, and list Escape for a device check. (Phases 15b, 16a)
- **Don't start a modal overlay while a toast is up.** VoiceOver stays inside the modal, so the toast wouldn't be read. Start it when the toast's binding returns to `nil`. (Phase 16a)

## 8. iPad and window sizes

**Do this**
- Decide every layout from the window in one place, never from the device.
- Test that decision with sizes measured on the simulator, including Split View and Stage Manager widths.
- Run iPad UI tests in their own CI part, and skip them on phones inside the test.
- Record iPad snapshots at 1x.

**Lessons**
- **Decide layouts from the window in one place.** One enum takes the window's width (from `onGeometryChange`), height, size classes and text size and returns each screen's layout. Snapshot tests draw the same container views the screens use. (Phase 15a)
- **A bottom tab bar on iPadOS 26.** A regular-width `TabView` puts its bar at the top; `.tabViewStyle(.tabBarOnly)` keeps it there. Giving the `TabView` `.environment(\.horizontalSizeClass, .compact)` draws the iPhone's bottom bar with the system's selection and VoiceOver. Read the real class above the `TabView` and hand it back to each tab's content, or every screen thinks it's on a phone. No API backs this; check it on each new iPadOS. If it stops working the bar just returns to the top. (Phase 15a)
- **Bars on iPad.** With the bottom tab bar, the iPad Pro 11-inch has 86 pt at the top and 77 at the bottom in both orientations. (Phase 15a)
- **Window widths.** On the 11-inch iPad held sideways, about two thirds, a half and a third came out at 795, 618 and 416 points; 795 was regular width, the others compact, and nothing went below 375. (Phase 15a)
- **Two panes or one column, chosen in a still image too.** `ViewThatFits(in: .horizontal) { sideBySide.frame(minWidth: 720, idealWidth: 720, maxWidth: 1120); stacked }` picks panes only when 720 points are offered, and `ImageRenderer` makes the same choice. Tell each pane which branch it's in, and keep the stacked branch identical to the old phone column so phone snapshots don't change. (Phase 15b)
- **A form sheet that fits its content on iPad.** `.presentationSizing(.form.fitted(horizontal: false, vertical: true))` did nothing while `.presentationDetents` was set; set detents only on a compact window. Read the width class in a `ViewModifier` around `.sheet` from the presenting view. A `ScrollView` offers no height, so measure the content with `onGeometryChange` and give it `.frame(idealHeight:)`. (Phase 15b)
- **One drawing, several arrangements.** Keep every rect in a plan struct and build new plans by moving whole groups (furniture with its labels and tap area) and scaling around them, as CSS `transform: scale()` does. Labels can't drift, and a test checks every control stays 44 pt and apart in every plan and window. (Phase 15a)
- **Resize a window from a UI test.** On an iOS 26.5 iPad simulator, Windowed Apps is on (on the hosted runner too). Drag the bottom-right corner with `press(forDuration:thenDragTo:)` on coordinates from `app.coordinate(withNormalizedOffset: .zero)`. iPadOS resizes about the centre, so the corner moves half the change; loop until `app.windows.firstMatch.frame` is close. The size survives a relaunch, so reset it at the start of each test. SpringBoard's `frame` is the screen in portrait whatever the orientation. (Phase 15a)
- **iPad-only UI tests in a shared suite.** Skip with `XCTSkip` when `UIDevice.current.userInterfaceIdiom != .pad`, inside the test's `@MainActor` launch helper (`setUpWithError` can't be made `@MainActor` in an override). Phone runs pass over the class in seconds. (Phase 15a)
- **iPad snapshots at 1x.** A whole 13-inch window at 2x is several megabytes; 1x with the same tolerances still catches a moved drawing or changed text. (Phase 15a)

## 9. Snapshot testing

**Do this**
- Render with `ImageRenderer` and hand the `UIImage` to swift-snapshot-testing. Never use the library's view strategy in a package test target.
- Give components a still-image environment flag that swaps UIKit-backed and lazy views for plain SwiftUI.
- Pin the simulator runtime, and fail clearly on any other.
- Record and collect artifacts through `TEST_RUNNER_` variables.
- Open every recorded PNG. Then check the real screen on the simulator, because snapshots have no bars, sheets or loading.

**Lessons**
- **Draw SwiftUI snapshots with `ImageRenderer`** (checked with swift-snapshot-testing 1.19.6). In a package test target with no host app, `.image(layout:traits:)` renders through `layer.render(in:)`, which drops `.blur`, and `.sizeThatFits` measured before the AX5 trait applied, so text was cut off. `ImageRenderer` with `proposedSize = ProposedViewSize(width: w, height: nil)`, `scale = 2`, and `.colorScheme`, `.dynamicTypeSize` and `.locale` set on the view draws blur and real text sizes. Pass the image to `assertSnapshot(of:as: .image(precision:perceptualPrecision:scale:))`. `drawHierarchy` needs a host app. (Phase 2b)
- **A lazy grid in a still image can come out a different height in each process.** On the iOS 27.0 simulator, a sheet with a `LazyVGrid` of eight tiles drew 675 or 693 points tall (the page moved down 9) depending on the test process, and the reference flipped between the two over three re-recordings. `UIHostingController.sizeThatFits` varied the same way, so measuring first didn't help, and proposing a fixed height changed other pages' layouts. Drawing the grid with a plain `Layout` under the still-image flag fixed it: 5 of 5 full runs passed. (Phase 20a)
- **Hand swift-snapshot-testing a plain 8-bit sRGB bitmap.** It turns the new image into PNG data before a pixel comparison, and on iOS 27.0 CI that step sometimes failed for an `ImageRenderer` image ("Newly-taken snapshot's data could not be loaded"). The spike now redraws `renderer.cgImage` into an 8-bit sRGB `CGContext` first. It couldn't be reproduced locally, so that fix is a defence, not yet proven by CI history. (Phase 20a)
- **Same runtime, same pixels.** The iOS 26.5 runtime (23F77) gave matching images locally and on `macos-26` at `precision: 0.995, perceptualPrecision: 0.98`, and re-recording gave byte-identical PNGs. Pin the runtime in the simulator-picking script and add a test that fails with a clear message on any other. (Phase 2b)
- **Record and collect artifacts through `xcodebuild`.** `TEST_RUNNER_`-prefixed variables reach the test process: `TEST_RUNNER_SNAPSHOT_TESTING_RECORD=all` re-records, `TEST_RUNNER_SNAPSHOT_ARTIFACTS=<dir>` collects failures for upload. `.snapshots(record:)` on a suite overrides the variable, so don't. (Phase 2b)
- **Exclude the reference folders.** swift-snapshot-testing writes `__Snapshots__` beside the test file, so a test in `Tests/X/Home/` needs `exclude: ["Home/__Snapshots__"]`. A test target can load module assets with `UIImage(named:in: .module, compatibleWith:)`. (Phase 4)
- **`ImageRenderer` can't draw UIKit-backed views.** `TextField`, `ScrollView`, `ProgressView` and `Toggle` come out as a yellow no-entry box. A still-image flag swaps in plain SwiftUI that looks the same; real controls get UI tests. A custom SwiftUI spinner avoids the problem. (Phase 2b)
- **Stand-ins must take exactly the space of the real view.** A sideways scroll view's `.fixedSize()` stand-in still reported its full width and pushed the snapshot off-centre; a tiny `Layout` that reports the proposed width fixed it. A vertical one must be able to shrink (see chapter 7). (Phase 2b)
- **Lazy stacks and grids: drop the scroll view, or go eager.** A `LazyVGrid` outside a `ScrollView` draws whole, so one snapshot shows every cell. A `LazyVStack` was measured from estimates and came out cut off; draw a plain `VStack` under the still-image flag. (Phases 6, 12a)
- **A custom `Layout` must cope with an infinite proposal.** A stack asks its children how wide they could be with `.infinity`, and `Int(width / column)` on that traps. A still-image grid layout crashed the whole snapshot test process on CI that way; give a non-finite width one column at the minimum. (Phase 21a)
- **Tall pages.** With no proposed height, a tall page laid out shorter than it measured (transparent bands, squeezed rows); `.fixedSize(horizontal: false, vertical: true)` before rendering matched the simulator. A page of 6,434 points at AX5 rendered empty at `scale = 2` and the library recorded its "size was zero" placeholder as the reference; it drew at `scale = 1`. Give the helper a scale parameter and look at every PNG. (Phases 5b, 7b)
- **Pass the safe area in.** A still image has none, so measure the simulator's once and pass it to full-screen views. (Phase 5b)
- **`.accessibilityFocused` draws as empty space.** Apply it only when not drawing a still image. (Phase 7a)
- **Measure only on screen.** `onGeometryChange` writing to `@State` during `ImageRenderer` changed three images whose content held lazy grids. Attach measuring only in the on-screen branch. (Phase 15b)
- **Snapshot a coach mark at the real control with an anchor preference.** `.anchorPreference(key:value: .bounds)` on the target, read with `.overlayPreferenceValue` and a `GeometryReader`, resolves in the same layout pass, so the spotlight lands on the control with no hand-measured rects. (Phase 16b)
- **`ImageRenderer` follows the environment for appearance and phase.** With `.colorScheme` set to `.dark`, asset images render their Dark SVG, so one snapshot can stack light above dark. Setting `.scenePhase` to `.inactive` records a privacy cover; set `.active` for the normal images. (Phases 5a, 12b)
- **Snapshots don't show what a half-height sheet hides.** The snapshot showed both buttons, but the half-height sheet cut off the second. Open sheets whose main content is a picture plus actions at `.large`. (Phase 12b)
- **If a snapshot run hangs, sample the process before blaming the code.** Every test started and none finished; `sample <xctest pid>` showed the main thread in the first `ImageRenderer`, inside `UIScreen` set-up waiting on the simulator. Shut it down, `simctl boot`, wait for `simctl bootstatus`, rerun. (Phase 10b)
- **Low-scale tolerance can hide copy changes.** At 1x, two stale lines of text and a missing row still passed the image diff. After any copy change, re-record every affected snapshot and compare each image by eye. (Stage A audit)
- **A snapshot cropped to the window hides a page that runs off the edges.** Measure the page's width when offered the window's width and fail if it's wider. That caught a Laundry page 33 pt too wide at AX5 and a search field 0.7 pt too wide. (Stage A QA)
- **Back small cosmetic fixes with a geometry check.** A wrapped iPad tag passed snapshot tolerance at 0.5%. (Stage A QA)
- **A still snapshot needs its images preloaded.** `ImageRenderer` draws once and can't wait for an async image load, so every real photo came out as its placeholder. A test-only hook on the image loader that reads the bytes synchronously, and a `.snapshotPhotos()` modifier that puts that loader in the environment, made every screen snapshot show the real photos at whatever size each view asks for. (PR #57)
- **Re-record only what failed.** `TEST_RUNNER_SNAPSHOT_TESTING_RECORD=failed` rewrites just the references that no longer match, so the diff holds only the images the change touched (109 screen snapshots here) and each can be opened and checked. `all` rewrites every file. (Real-photo audit fixes)
- **A brand-new snapshot's first recording on CI is lost.** With no reference, swift-snapshot-testing writes the image beside the test file on the runner and fails; `SNAPSHOT_ARTIFACTS` only collects mismatches, so nothing comes back to download. Commit a reference recorded locally first: if CI's runtime draws it differently, the mismatch then lands in the artifacts. Settings screens recorded on the iOS 26.5 simulator matched CI's iOS 27.0 within 0.995 and 0.98. (Phase 21b)
- **Every snapshot helper should draw through the 8-bit sRGB redraw.** One suite with it and one without: the one without failed on iOS 27.0 CI with "Newly-taken snapshot's data could not be loaded". Keep the helper in the shared test-support target. (Phase 21b)

## 10. UI testing (XCUITest)

**Do this**
- Use one shared wait that checks at once, then every 0.25 s, bounded at 30 s.
- After every tap, wait for the change it causes. Tap once more only if the change didn't come and the control is still there.
- Scroll with a drag that holds still. Check an element is clear of the bars, not just `isHittable`.
- Put identifiers on elements, not their stacks.
- Give every launch the same base arguments, and a Debug-only flag that turns off UIKit animations.
- Assert on lasting results, never on short toasts.
- Keep app launches few; cover data paths in package tests.

**Waits and taps**
- **`waitForExistence` and `XCTNSPredicateExpectation` first look a second after they start**, even when the element is already there, then once a second. With about 774 `waitForExistence` calls and hundreds of predicate waits per run, that first second cost at least 13 minutes of runner time. A shared wait that checks at once, then every 0.25 s from a run-loop `Timer` while `XCTWaiter` waits on an `XCTestExpectation` (`assertForOverFulfill = false`), cut summed UI test time on CI by about a third. Two tests had relied on that second; make those waits explicit (for the old screen to go, or a frame to stop changing). (Stage A)
- **Bound waits at 30 s.** On a loaded runner a back tap took over 5 seconds to land and single queries took up to 55; 15-second waits failed tests that passed on retry. A long bound costs nothing when the condition holds early. (Phase 5b, Stage A)
- **Wait for the state a tap changes before reading it.** `XCTAssertTrue(chip.isSelected)` straight after `chip.tap()` failed on CI. Tap, wait for `selected == true`, and tap again if the first was lost. The same goes for a tab tapped right after launch, a sheet's Close tapped while it's still rising, Back, and any button that moves to another screen (an onboarding Continue): wait for the next screen and tap again only if it didn't come and the button is still there. Even after the other fixes, about one tap a run was lost. (Stage A)
- **Wait for the pushed screen to go, not only for the one under it.** After Back, the previous screen's bar exists while the pushed one is still sliding away, and an early tap was lost. A shared `goBack(from:to:)` waits for the pushed bar to stop existing. (Phase 11)
- **Type only once the field has the keyboard.** `typeText` right after `tap()` failed with "Neither element nor any descendant has keyboard focus" when the tap arrived 15 seconds late. Wait for `hasKeyboardFocus == true` (it works as a predicate) and tap again if it doesn't come. (Stage A)
- **XCUITest taps a text field in the middle, so the cursor can land at the start.** `field.coordinate(withNormalizedOffset: CGVector(dx: 0.97, dy: 0.5)).tap()` puts it at the end before deleting. (Phase 7b)
- **Don't assert on a short toast.** On CI XCUITest spent about 9 seconds waiting for the app to settle after Save, and a 4-second toast was gone; a 6-second Undo toast was missed twice. Check the lasting result, or pass a Debug-only flag that keeps toasts up longer in the one test that needs the toast. (Phase 7b, Stage A)

**Scrolling and hittability**
- **Scroll with a drag that holds still, not a swipe.** After `swipeUp()` the page glides on and a tap only stops it. `coordinate.press(forDuration: 0.05, thenDragTo: end, withVelocity: .fast, thenHoldForDuration: 0.3)` leaves no momentum. Keep the drag in the top half, above the keyboard. Don't swipe down on an open sheet to scroll it; that can start closing it. (Phase 11, Stage A)
- **An element under the iOS 26 navigation bar still counts as hittable.** A control half under the glass bar passed `isHittable`, and the tap went to the bar. Scroll until `element.frame.minY >= app.navigationBars[title].frame.maxY`, assert it, then tap. The screen recording in the failed `.xcresult` (`xcrun xcresulttool export attachments`, frames pulled with `AVAssetImageGenerator`) showed the cause. (Phase 18)
- **Asking `isHittable` can fail the test by itself** ("Failed to determine hittability ... Activation point invalid"). Where a fallback is needed, compare the element's frame with the window instead. (Stage A)
- **`for _ in 0..<n where !element.isHittable` asks on every pass**, even after the element is found, and each ask is a query (0.3 to 1 s on CI). Check inside the loop and break. (Stage A)

**Finding elements**
- **An identifier on a container replaces its children's identifiers.** A sheet's `VStack` with an identifier hid its buttons' and a note's identifiers. Put identifiers on elements; if a container needs one, add `.accessibilityElement(children: .contain)` before it. A `ScrollView` with an identifier didn't do this. Inside a `ContentUnavailableView` that has an identifier, match a text by its label instead. (Phases 3, 5a, 12a, 12b)
- **Numbers in labels are formatted for the locale** ("2,117"); strip non-digits before comparing. (Phase 3)
- **Find the system share sheet by its identifiers.** `UIActivityViewController` is `otherElements["ActivityListView"]` and closes with `buttons["header.closeButton"]` on iOS 26.5. Wait for the close button before tapping; swiping the sheet down left it open. Wrap the controller yourself when the screen needs to know whether something was sent: `completionWithItemsHandler` reports it, `ShareLink` doesn't. (Phase 14b)
- **Opening a screen with a sheet up breaks tests that tap Back.** The sheet covers the bar ("No way back"). Close the sheet first. (Phase 10a)

**Launch state and speed**
- **Once any state outlives a launch, UI tests share it.** Tests on one simulator run in the same app container. Give every launch a shared `standard` argument array that sets what it relies on (tours off, onboarding skipped without writing anything) and let only the first-run test reset. Relaunch with `app.terminate()`, new `launchArguments`, `app.launch()`. (Phase 17)
- **A Debug-only flag that turns off UIKit animations (`UIView.setAnimationsEnabled(false)`) speeds up flows.** XCUITest waits for idle after every action. Three classes went from 283 to 235 seconds locally, and summed CI time from about 45 to 35 minutes. Keep it out of tests about animated things (tours, onboarding, iPad layouts) and check it isn't in a Release binary. (Stage A)
- **Open long debug pages at the part a test needs.** Swiping through a whole component catalog took 45 to 140 seconds per test on CI. A Debug-only `-catalog -catalog-page search` cut the class from 411 to 113 seconds with the same checks. (Phase 12b)
- **Watch launches as UI tests grow.** Two extra tests with five launches added 45 seconds locally and pushed the CI job from 5 to 7 minutes up to 8.5 to 13.5. (Phase 3)
- **UI tests at a given text size and orientation.** Launch with `-UIPreferredContentSizeCategoryName UICTContentSizeCategoryAccessibilityXXXL` (AX5; `...AccessibilityXL` is AX3) and set `XCUIDevice.shared.orientation`. The orientation stays after the test, so reset it with `addTeardownBlock { @MainActor in XCUIDevice.shared.orientation = .portrait }` (`tearDown` isn't main-actor isolated). (Phase 5b)
- **The simulator measures scroll duration, not hitches.** `XCTOSSignpostMetric.scrollingAndDecelerationMetric` reported only duration. Hitches need a device. Keep such tests behind `TEST_RUNNER_<NAME>=1` (seen in the test as `<NAME>`) and `XCTSkipUnless`. (Phase 6)

**Looking at real screens**
- **A throwaway UI test is the way to see real screens.** When nobody can grant the simulator panel, a test that's never committed walks the app and writes `XCUIScreen.main.screenshot().pngRepresentation` straight to a Mac path (the simulator shares the file system), one PNG per screen. Orientation and window width can come from `TEST_RUNNER_` variables. It needs no permission prompt and shows bars, sheets and toasts that snapshots don't. One such walk found a crash the committed tests never reached. Landscape PNGs sometimes come out rotated. Keep the file out of the repo. (Phases 12a, 13, 15b)
- **The system Files sheets are reachable from XCUITest.** SwiftUI's `fileMover` sheet answers to `app.buttons["Save"]`, and `fileImporter`'s browser lists files as elements labelled with their names, so a throwaway test can export to On My iPhone and pick the file again after a reinstall. The saved file is under the simulator's `data/Containers/Shared/AppGroup/<id>/File Provider Storage/`, which survives deleting the app. The welcome button under the picker still "exists" while the picker is up, so wait for the picker's own elements, not for the button to go. (Phase 21b)
- **Check a sideways layout by eye.** Orientation persists on the simulator, so a one-line test that rotates it, then `simctl launch` and `simctl io screenshot`, shows the sideways app (the PNG is in portrait framing). (Phase 5b)
- **Some elements never report hittable but still take a tap.** A confirming-tap helper that waits for `isHittable` should fall back to `exists` for those, then confirm the tap by its effect. (Stage A audit)
- **Don't put `accessibilityIdentifier` on a SwiftUI alert's button.** On iOS 26.5 the button then appears twice in the tree (one nested in the other, same frame, identifier and label), the query matches two elements, and it never counts as hittable, so a confirming tap waits out its timeout. Find alert buttons by their label instead. (Phase 21a)
- **Two `xcodebuild test` runs on one simulator kill each other.** Starting a second run while the first was still testing ended both runners' tests with "Test crashed with signal kill". Run one at a time per simulator, and check `pgrep -fl xcodebuild` before starting another. (Phase 21a)
- **Scroll a split pane by dragging inside that pane.** A drag in the middle of the screen scrolls whatever sits there, so a sidebar's bottom tiles looked unreachable. (Stage A QA)

## 11. Swift Testing and concurrency

**Do this**
- Mark plain value types `nonisolated` in modules with main-actor default isolation.
- Let heavy main-actor tests take turns through a custom trait, and bound polling waits by turns, not seconds.
- Measure performance serially and bound it loosely, with extra room on CI.
- Keep shared test helpers and contract suites in a library target that imports Testing.
- Pass closures, not key paths or `mutating` calls, inside `#expect`.

**Swift Testing**
- **`#expect` and `#require` gotchas.** Key paths inside the macro fail with "call can throw, but it is not marked with 'try'": write `items.contains { $0.isArchived }` and `allSatisfy { $0.flag }`. A `mutating` call on a local fails (`$0` is immutable): call it first, then expect on the result. A `#require` nested in another `#require` fails with "recursive expansion of macro": unwrap in two steps. `@Test(arguments:)` with tuples of more than two values didn't compile: pass one value and switch on it. (Phases 3, 8b, 11, 16a)
- **A plain SwiftPM library target can `import Testing` when only test targets depend on it.** Shared store contract suites then live in one place, every store's test target runs them, and each check shows as its own test. (Stage A audit)
- **Performance tests: measure serially, bound loosely.** Record numbers with `-parallel-testing-enabled NO`. Bounds of 500 ms to 1 s over 36 to 41 ms Debug timings catch big regressions. On a busy CI runner a 6 ms check once took 862 ms, so take the fastest of three runs and allow three times the bound when `CI` is set (passed as `TEST_RUNNER_NOOK_CI`). (Phases 3, 8a)

- **After a test failure, `xcodebuild` spends 10 minutes collecting simulator diagnostics** ("Failure collecting diagnostics from simulator: Timed out after 600.0 seconds"). Pass `-collect-test-diagnostics never` to local runs that only need the result. (Phase 21b)
- **Command-line builds don't add new strings to a package's String Catalog.** Only Xcode's editor does. Add the keys yourself (the literal with `%@` or `%lld` for each interpolation, plus plural variants), or the build still works but the catalog falls behind. (Phase 21b)

**Main actor and test scheduling**
- **In a big target, every main-actor test waits behind every other one.** Swift Testing starts all tests at once and the main actor runs jobs in arrival order. With about 300 snapshot tests, each drawing on the main actor in one go, almost every test finished only as the target drained: median 15 s of 20 s locally, about 200 s on CI, where trivial tests "passed after 84 seconds". The sign: the log goes quiet, then everything passes at once. `sample <pid>` of `xctest` shows what holds the main thread. (Phase 18)
- **Let heavy main-actor tests take turns with a custom trait.** A `SuiteTrait, TestTrait, TestScoping` whose `provideScope` takes a turn from an actor (a FIFO of `CheckedContinuation`s), with `isRecursive` true and a scope per test case (`testCase == nil ? nil : self`), lets one tagged test at a time use the main actor. Tag the snapshot suites and big speed checks. The target takes as long, but the median test dropped from 15 s to under 5 s locally and from about 200 s to 46 s on CI. (Phase 18)
- **Bound a polling wait by its turns, not seconds.** Even with turns, a wait took 30 s mid-run on CI while locally it needed one or two 5 ms polls. A bound of 1,000 turns is about 5 s on a free main actor, survives any runner and still catches a real hang. Size it with a throwaway draft PR that prints each wait's time and turns. (Phase 18)
  - Superseded: raising a seconds bound until CI passes (20, 60, then 600 s). It hid the queueing problem. (Phase 17)

**Concurrency**
- **Main-actor default isolation reaches further than you expect.** With `.defaultIsolation(MainActor.self)`: tests touching the module's types need `@MainActor` or `#expect` fails to compile; members added in extensions on SwiftUI types (a `Color` initializer, a `static let`) are main-actor isolated, so a `nonisolated` token struct can't call them, and they need `nonisolated`; a plain value type used as a default argument of a `nonisolated` initializer fails with "main actor-isolated default value in a nonisolated context", so mark the type `nonisolated`; and a custom `Layout`'s methods are nonisolated, so constants they read need `nonisolated static`. (Phases 1a, 2a, 17)
- **`@MainActor () -> Void` is implicitly `Sendable` in Swift 6.** Passing a plain stored closure (`var edit: () -> Void`) to that type fails with "converting non-Sendable function value". When a main-actor class only stores and calls it, type it `() -> Void`. (Phase 16b)
- **Swift 6.3.3 crashed compiling a `Binding` whose setter was a stored `@MainActor @Sendable` closure.** `Binding(get: { isOn }, set: set)` crashed IR generation with no error at the line. `set: { set($0) }` compiled. If a build stops with "Command SwiftCompile failed" and a stack dump, read the "While emitting IR" line for the file and look for a function value passed straight to an isolated parameter. (Phase 14b)
- **Keep `withAnimation` to the control that needs it.** A segmented switch that set its value inside `withAnimation` animated the whole page, SwiftUI drew it on `com.apple.SwiftUI.AsyncRenderer` and called the switch's `ForEach` content there, and Swift 6's main-actor check stopped the app (`EXC_BREAKPOINT` in `_dispatch_assert_queue_fail`). Set the value plainly and animate only the pill with `.animation(_:value:)`. The crash report in `~/Library/Logs/DiagnosticReports` names the thread and closure. (Phase 15b)
- **Swift 6.4 (Xcode 27.1) crashed compiling a `Task` whose closure had typed throws.** `Task { () async throws(AccountProblem) -> AccountUser in try await account.whoAmI() }` stopped IR generation with a stack dump ("While emitting IR SIL function ..."). A `Task { () async -> AccountProblem? in ... }` that catches and returns the error compiled. Typed-throws closures passed as plain non-escaping parameters were fine. (Phase 24a)
- **Run one-time async setup through a stored `Task` every caller awaits.** A `Bool` set before the first `await` lets a second caller through mid-setup. Keep the `Task` and await its value everywhere; test with two `async let` callers. (Phase 16b)

## 12. Data, privacy and security

Covers data classification, the data map, threat model, privacy manifest, permissions and local storage. Backend, secrets and server-side limits come later (chapter 15).

**Do this**
- Turn on complete Data Protection in the entitlements.
- Cover sensitive screens while `scenePhase != .active`, and check the file iOS keeps.
- Make sensitive value types unprintable.
- Make every store erasable through its protocol and report deletion part by part.
- Keep only the lowest-tier flags across launches until real storage exists, and declare every required-reason API.

**Lessons**
- **Data Protection** goes in the entitlements as `com.apple.developer.default-data-protection = NSFileProtectionComplete`. A simulator build shows it in the `*-Simulated.xcent` file under DerivedData, not in `codesign -d --entitlements`. (Phase 1a)
- **Hide sensitive images with `scenePhase`.** A view that draws a plain backdrop while `scenePhase != .active` keeps the picture out of the app switcher's snapshot. Over a scrolling screen the cover needs `.ignoresSafeArea()`, or content under the navigation bar's blur shows through. (Phases 12b, 14a)
- **Check the app switcher snapshot by reading the file iOS keeps.** After `XCUIDevice.shared.press(.home)` in a throwaway UI test, it's in the app's data container (`xcrun simctl get_app_container <udid> <bundle id> data`) under `Library/SplashBoard/Snapshots/sceneID:<bundle id>-…/` as `.ktx` files; `sips -s format png <file> --out <png>` converts them. Only the latest state is kept, so check one per run. (Phase 14a)
- **Make a Sensitive value type unprintable.** `CustomStringConvertible` and `CustomDebugStringConvertible` returning "redacted" plus `CustomReflectable` with no children keep values out of `print`, interpolation, `String(reflecting:)` and `dump`. Test each one. (Phase 14a)
- **Make every store erasable through its protocol, and report deletion part by part.** Every store protocol refines `ErasableStore` (`eraseAll()`). A `DataDeletionService` erases each part, keeps going past a failure and reports deleted, pending or failed per part. A test fills every store, deletes, and checks each matches the empty fixture set. Server data later becomes another part that can be pending. (Phase 14b)
- **After deleting, rebuild the whole tab tree.** Put the tabs, their paths, image caches and unsent drafts in one child view with `.id(generation)` and bump it after a complete deletion, so nothing from before can show on a screen that was open. (Phase 14b)
- **Keep only the lowest-tier flags until real storage exists.** A `UserDefaults` suite of the app's own (not an App Group) behind the existing store protocols kept onboarding done, the starting data set, each tour's seen version and the tips switch, and nothing else. Split records that mix tiers. Read defensively: a value of the wrong type means "not done", so the worst case is showing something again. (Phase 17)
- **Test `UserDefaults` stores on a suite per test.** A random suite name removed with `removePersistentDomain(forName:)` in a helper's `deinit` isolates tests; a "relaunch" is a second store on the same suite. `persistentDomain(forName:)` returns exactly what's in the file, so a test can prove only the expected keys are written. (Phase 17)
- **Test "the app was closed" without a disk.** A unit test builds a second screen model on the same store. The UI test terminates and relaunches with a launch option that seeds the same draft. When real storage arrives, only the store changes. (Phase 7b)
- **Wrap SwiftData migrations in a journal and a snapshot.** A custom `MigrationStage` saves more than once, and the schema change commits before `didMigrate` runs. Killed with SIGKILL halfway, a store reopened as the new version with half its migrated records and never finished. Journal each step in a file next to the store, copy the store first with `NSPersistentStoreCoordinator.replacePersistentStore` (it handles `-wal` and `-shm`), record IDs, counts and file hashes, verify after, and put the snapshot back on any journal short of "verified". 64 real kills all recovered. Read the store's version from `metadataForPersistentStore` and `NSManagedObjectModel.makeManagedObjectModel(for: Schema)` before opening anything, so an unknown version goes to recovery instead of a reset. (Phase 20a)
- **Write old-version test fixtures through Core Data, not old `@Model` classes.** Once a process has opened a newer schema, SwiftData maps every model with that class name to the newest entity, and saving an old-version object crashes ("not key value coding-compliant for the key ..."). Build the old `NSManagedObjectModel` from its `VersionedSchema` and insert with `setValue(_:forKey:)`. (Phase 20a)
- **SwiftData sorts strings with a localized, number-aware comparison,** not code-point order ("70fb" before "561b"). Sort in Swift when the exact order of IDs matters. (Phase 20a)
- **Keep `CKSyncEngine`'s state as a row in the store.** The engine writes no state file of its own and its `State.Serialization` is `Codable`. Saved after the records it describes, with the store's protection class, it can only fall behind them, and CloudKit then resends the changes. A separate file needs no Data Protection exception. (Phase 20a)
- **Declare `UserDefaults` in the privacy manifest:** `NSPrivacyAccessedAPICategoryUserDefaults` with reason `CA92.1` for data only the app reads. (Phase 17)
- **An encrypted export with no dependency: AppleArchive's `hkdf_sha256_aesctr_hmac__scrypt__none` profile.** Write with `ArchiveEncryptionContext(profile:compressionAlgorithm:)`, `setPassword`, `authData` for a clear marker, then `ArchiveByteStream.encryptionStream` and `ArchiveStream.encodeStream`, writing each file as a header (`TYP`, `PAT`, `DAT` blob) and `writeBlob` in chunks, so nothing unencrypted touches the disk. Read the same way, header by header, with `readBlob` in chunks, and check every path, type and size yourself instead of using the extract stream. Verified behaviour (Xcode 27.1, iOS 26.5 and macOS 27): a wrong passphrase fails when the decryption stream is made, and a very short one already at `setPassword`; a changed or cut byte fails AEA's authentication as it's read; **bytes appended after the end are ignored**, so compare the file size with the context's `containerSize` after reading. A Mac opens it with `aea decrypt -i <file> -o x.aar -password <file>` then `aa extract -i x.aar -d <dir>` (`aea` has no prompt). (Nifty Outfit Nook, Phase 21b)
- **`replacePersistentStore` copies a live store's data into the copy's own `-wal`.** A store copy shipped as one file lost most of its records. Checkpoint the copy first (`sqlite3_wal_checkpoint_v2(..., SQLITE_CHECKPOINT_TRUNCATE, ...)`, then `PRAGMA journal_mode=DELETE`) and run `PRAGMA integrity_check`. Copying from the open store this way is fine; writing into it isn't (20a's SQLITE_BUSY). (Phase 21b)
- **Restore into a running SwiftData app in one save, then rebuild the store actors.** One `ModelContext.save()` is one SQLite transaction, so a kill at any step leaves the old data or all the new data (tested at six checkpoints). Actors that cache what they read must be replaced afterwards, and deleting and re-inserting a changed row (rather than editing it) keeps other contexts from holding a stale object; the unique constraint on kind and key allows both in one save. (Phase 21b)
- **A new field on a value type stored as JSON needs a payload version bump, even when old JSON still decodes.** `JSONDecoder` ignores keys it doesn't know, so an older build reads a newer record without the field and drops it at its next save, with no error. Bump the payload version so older builds refuse the record, and the export manifest's version so they refuse the copy. Synthesized `Decodable` requires every non-optional key even when the property has a default, so give the type an `init(from:)` that reads the new field with `decodeIfPresent(...) ?? []`; old JSON then decodes as it is and nothing needs rewriting. (Nifty Outfit Nook, Phase 21c)
- **`@Attribute(hashModifier:)` gives a SwiftData store a new version with the same columns.** When only the meaning of a column changes (here: the store may now hold payloads an older build can't read), freeze the old `@Model` class inside the old `VersionedSchema` enum, add the hash modifier to the current class, and list a `.lightweight` stage. The migration ran through the journal with every payload byte for byte, and an older build's `isConfiguration(withName:compatibleWithStoreMetadata:)` check rejected the new store before opening it, so it showed "saved by a newer version" and left the file alone (checked on the iOS 26.5 simulator by installing the older build over the new store). (Phase 21c)
- **Make the old-schema fixtures with the old build before changing the schema.** A throwaway test run on the last commit before the change wrote the demo store as one file (checkpointed), an export and a raw store copy, plus every row as stored. The new build's tests then migrate and restore files the old code really wrote, which a fixture written by the new code can't prove. Same-process test schemas can't stand in for it (20a: SwiftData maps a class name to the newest entity). (Phase 21c)
- **Compare decoded values, not JSON bytes.** Two `JSONEncoder` encodings of the same struct in one process came out with their keys in a different order, so a byte comparison reported a changed record that wasn't. Use `.sortedKeys` where bytes must match, or decode and compare with `==`. (Phase 21b)

## 13. Images and photos

**Do this**
- Use `PhotosPicker`, and strip metadata yourself: keep only a copy rebuilt from the pixels, never the bytes she picked.
- Downsample with ImageIO to half the photo or less, and refuse huge files before decoding.
- Use Accelerate for pixel work, off the main actor, cached by what the image shows.
- Don't trust Vision on the simulator; skip those tests with a probe and build the device path.

**Lessons**
- **`PhotosPicker` needs no permission and no Info.plist key on iOS 26.** It shows "Private Access to Photos" and, by default, "Location Is Included", so picked data can carry GPS. A PNG written from pixels with `CGImageDestinationAddImage(destination, image, nil)` has no EXIF, GPS or TIFF; test it with a JPEG that has a made-up location. `preferredItemEncoding: .current` gets the stored HEIC without conversion. (Phase 8a)
- **Downsample with ImageIO and keep the working size at or under half the photo.** `CGImageSourceCreateThumbnailAtIndex` with `ThumbnailWithTransform` applies EXIF orientation and doesn't enlarge small photos. For a 4,032 x 3,024 JPEG, 1,536 px took about 30 ms and 2,048 px 85 ms or more: up to 2,016 the decoder halves while decoding. Check the pixel count from the properties first. (Phase 8a)
- **Vision's foreground mask can't be trusted on the simulator, and fails differently by host.** On an Apple-silicon Mac, `VNGenerateForegroundInstanceMaskRequest` fails on the iOS 26.5 and 27.0 runtimes with error 9 ("Could not create inference context"); on `macos-26` it ran and found no subject. Under `#if targetEnvironment(simulator)` return a typed `unsupported` after validating input, skip mask tests with `.enabled("reason") { await probe() }` (one cached `Task` trying a single cutout), and compile the device path with `xcodebuild build -destination generic/platform=iOS CODE_SIGNING_ALLOWED=NO`. The request runs on macOS, so a throwaway command-line harness gives real numbers. (Phase 8a)
- **Make a new `VNImageRequestHandler` for every measurement.** Reusing one returns the cached result in well under a millisecond. (Phase 8a)
- **Vision's masks are a fixed 512 x 512, not the photo's shape.** The instance mask is `OneComponent8` labels (0 is background) stretched over the image, so pixel fractions give coverage and normalized bounds directly. `generateMaskedImage(..., croppedToInstancesExtent: true)` returns premultiplied 32BGRA that wraps straight into a `CGImage` (`byteOrder32Little | premultipliedFirst`). Read edge softness from its alpha with `vImageHistogramCalculation_ARGB8888`. (Phase 8a)
- **Measure memory with `task_info(TASK_VM_INFO)`.** `phys_footprint` is what iOS counts; sample it every few milliseconds from a detached task and keep the maximum. `os_proc_available_memory()` returns 0 on the simulator. (Phase 8a)
- **Draw a sticker edge with a greyscale dilation.** Eight offset copies leave gaps by thin straps. `vImageDilate_Planar8` on the alpha with a round brush (0 inside the radius, rising to 255 over its last pixel) gives a soft round edge that keeps anti-aliasing. Double the alpha first (`vImageTableLookUp_Planar8`) or thin straps get see-through paper. 7 ms in Debug, against 1.7 s for a pure-Swift distance transform. Hot pixel loops crawl without optimisation, and package tests run in Debug, so use Accelerate. (Phase 8b)
- **Bake the shadow into the cached image, below only.** `CGContext.setShadow` with the offset at least as large as the blur leaves the rows above clear (test it), and costs nothing per frame. Size edge and shadow from the image's long side. (Phase 8b)
- **Render each image once, off the main actor, keyed by what it shows.** A main-actor cache with an in-flight task per key (two views share one render), a byte budget with LRU eviction, and a clear on memory warning kept it to one render per picture, size, scale and appearance. Key placeholders by kind and colours, and photo cutouts by picture reference, not record ID, so a new photo can't show a stale image. (Phase 8b)
- **A fallback should take exactly the image's space.** A photo tile fills the same frame the sticker fits, so falling back never moves the layout; crop to the subject bounds plus a margin. (Phase 8b)
- **Bundle transparent cutouts as JPEG 2000, not HEIC.** HEIC with alpha was the smallest, but the iOS simulator's HEVC software decoder hung on it: decodes never returned and the UI tests' accessibility queries froze. PNG was 16 MB for 51 cutouts. JPEG 2000 with alpha, which ImageIO decodes in software everywhere, worked on every simulator. (Sample wardrobe, PR #56)
- **JPEG 2000 costs a whole decode for any size over half.** ImageIO decodes smaller sizes from the file's half, quarter and eighth resolution levels: a 640 px cutout took about 3 ms at 48 px and 6 ms at 120 px, but 28 ms at anything from 330 px up. A full `CGImageSourceCreateImageAtIndex` decode is also lazy and only happens at the first draw, so draw it into a bitmap to really decode it. Decode once at full size the first time a size over half is asked for, keep it in a cost-limited `NSCache`, and scale every later size from it with Core Graphics (about a millisecond). For five display sizes of 51 cutouts on a Mac: 4.6 s decoding per size, 2.8 s decoding once and scaling. (Real-photo audit fixes)
- **Size a sticker's space from the cutout's real shape.** A shoes box tuned for drawn side views (116 x 48) left a photo of knee boots, 0.68 wide to 1 tall, a third the width of the bag beside it. Keep the cutout's pixel aspect with the cutout and give the layout a target area per role, shaped like the cutout and capped; drawings keep their old box. Re-run the every-mix layout tests with each real shape. (Real-photo audit fixes)
- **Fading a real photo changes its colour.** At 42% opacity on a cream card, a black skirt read as gray right above a note naming it black; desaturating it instead turned a taupe blazer gray. Fade a removed piece only a little and add a small mark, and say why in words. Drawn art with flat colours hid this. (Real-photo audit fixes)
- **Fit a tall photo into a shorter frame without bands or a lost head.** A 9:16 full-length photo can't fill a 4:5 frame without cutting the head or the feet, and fitting it left wide flat bands. Show it at the frame's full height, trimmed a few percent top and bottom, over a blurred copy of itself that fills the sides, with soft edges between them. Badges and tags placed for drawn art landed on her face: put them where the photo is empty, and leave them off pictures too small to keep them clear. (Real-photo audit fixes)
- **Look at every real cutout on dark and bright backgrounds.** Quality signals catch soft edges and pieces cut off by the frame, not a second object attached to the piece: 14 hung garments kept their hanger, and a tote kept the chair post through its handles. (Real-photo audit)
- **Strip a photo's metadata by rebuilding it from pixels, and test with planted values.** `CGImageSourceCreateThumbnailAtIndex` with `CreateThumbnailFromImageAlways`, `CreateThumbnailWithTransform` and `ThumbnailMaxPixelSize` set to the photo's long side gives the whole picture upright; `CGImageDestinationAddImage` with only the quality writes a JPEG with no GPS, IPTC, maker, model, serial, time or XMP. ImageIO still adds generic Exif fields of its own (colour space and pixel size, and for some pictures the Exif version, components, FlashPix version, scene type and resolution), so don't assert an empty Exif dictionary. Plant unusual strings in every metadata block of the test photo, check the original has them, then search the cleaned file's properties, XMP tags and raw bytes for them. (Phase 22a)
- **HEIC encoding hangs on the iOS 26.5 simulator.** `CGImageDestinationFinalize` for `public.heic` never returned: it waited in VideoToolbox's `VTTileCompressionSessionEncodeTile`, one encode at a time as well as several, and the test run sat idle until killed. Decoding a small HEIC worked on 26.5, but on CI's iOS 27.0 simulator the HEIC decode cases never finished: they held the test threads until no other test reported and the job hit its time limit, and the run went through once they were skipped. Write JPEG (or settle HEIC on a device), keep a small HEIC fixture made with ImageIO on the Mac (inline as base64), and run its cases on a device only (`#if targetEnvironment(simulator)` with a skip reason). Sample a stuck test process with `sample <pid>` to see where it waits. (Phase 22a)
- **The iOS 26.5 simulator shows the camera prompt and a camera that takes nothing.** `AVCaptureDevice.requestAccess(for: .video)` shows the system prompt with the purpose string, `UIImagePickerController.isSourceTypeAvailable(.camera)` is true, and the camera screen opens on a grey simulated viewfinder whose shutter does nothing; Cancel works. Test the permission flow there and real capture on a device. `xcrun simctl privacy <udid> grant camera <bundle id>` ends the running app; `reset` brings the prompt back. Photos added with `simctl addmedia` carry the GPS you wrote into them, and the picker shows "Location Is Included". (Phase 22a)
- **An English-only `InfoPlist.xcstrings` isn't copied into the app.** In a synchronized app folder, with English the only language, the build had no `.lproj` and no `InfoPlist.strings`; the purpose string came from `INFOPLIST_KEY_NSCameraUsageDescription` alone. Add the catalog with the first translation. (Phase 22a)
- **Measure scroll hitches with the app scrolling itself, not XCUITest swipes.** On the iOS 26.5 simulator the test runner's screen queries between swipes stalled the app's main thread on their own: two frames of about 75 ms every 3 seconds, even with nothing scrolling (5 to 10 hitches a pass). A Debug-only flag that finds the longest `UIScrollView`, sets its `contentOffset` from a `CADisplayLink` at a fixed speed, and counts late frames itself (later than 1.5 frames; hitch time is the time past the deadline) gave steady runs of 0.8 to 1.7 ms/s over 2,400 photo pieces, with the UI test only opening the screen and sleeping. Measure after a relaunch: the first launch straight after writing 4 GB of seed photos read 35 ms/s. (Phase 22b)
- **The simulator hides what thumbnails save; measure the decode instead.** On an Apple-silicon Mac, scrolling 2,400 full-size JPEGs with and without 512-pixel disk thumbnails gave the same hitch time (about 1.3 ms/s) and memory (89 MB). ImageIO's thumbnail call on the same files showed the difference: 18.5 ms to make a 480-pixel picture from a 1.9 MB, 12 MP original against 2.1 ms from its 30 KB thumbnail. Report that per-picture cost, and leave the hitch rate to a real phone. (Phase 22b)
- **Sweep orphaned files from the same reference list the export uses, and spare files written since launch.** One function that lists every image a record points to (pieces, cutouts, drafts and what they started from, the profile photo, stored pictures, review copies) serves the export and the clean-up, so the two can't drift. A new photo exists before the draft that points to it is saved, so the in-session sweep skips IDs written this launch and the next launch's sweep catches any that never got a record. Remove nothing when the store can't be read, and hold one lock with restore so neither sees the folder half way. (Phase 22b)

## 14. Release and TestFlight

**Do this**
- Archive an unsigned device build in CI and before every upload, and check what's in it.
- Prove debug and test code are absent from Release with `nm` and `strings`.
- Use timestamp build numbers from an ignored xcconfig.
- Mark sample-data builds TestFlight Internal Only.

**Lessons**
- **An unsigned device archive is a full rehearsal.** `xcodebuild archive -destination "generic/platform=iOS" CODE_SIGNING_ALLOWED=NO` builds the real Release archive with no team or certificate. Check its Info.plist (`ITSAppUsesNonExemptEncryption`, no `*UsageDescription`, no ATS key), the privacy manifest against `nm -u` (the required-reason APIs imported), `otool -L` (no XCTest or test packages), `strings` for build-machine paths, and the dSYM's UUID (`dwarfdump --uuid`). One script, run in CI and before every upload. (Phase 18, Stage A)
- **Prove debug and test code stay out of Release.** `nm` on the Release binary for the catalog's and the snapshot library's type names, and `strings` for Debug-only launch arguments, return nothing; the same check on the Debug `.debug.dylib` finds hundreds, which shows the check works. Add every new Debug-only page or flag to it. (Phases 2b, 9, Stage A)
- **An iOS 26 app icon can be a hand-written Icon Composer `.icon` folder.** It's SVG layers plus `icon.json`: `fill-specializations` for light and dark, and per layer `image-name-specializations` (with a default `{"value": "a.svg"}` beside `{"appearance": "dark", ...}`; a plain `image-name` plus a dark entry ignored the dark art) and `opacity-specializations` with `"appearance": "tinted"`. The `ictool` inside Icon Composer (`Icon Composer.app/Contents/Executables/ictool`) renders every appearance with `--export-image --platform iOS --rendition Default|Dark|TintedLight|TintedDark|ClearLight|ClearDark`. Drop it in a synchronized folder and delete the old `AppIcon.appiconset`. (Phase 18)
- **Don't write `nm "$binary" | grep -q pattern` under `set -o pipefail`.** grep stops at the first match, nm dies of SIGPIPE, and the pipeline counts as failed, so the check passes exactly when it should fail. Read the output once into a variable and `grep -q pattern <<<"$symbols"`. Run every "nothing debug in Release" check against the Debug binary too, to see it fail. (Phase 20a)
- **SwiftPM copies a package's resources into the app in every configuration.** `EXCLUDED_SOURCE_FILE_NAMES` and an `EMBED_PACKAGE_RESOURCE_BUNDLE_NAMES` override in the Release xcconfig both left the bundle in place, and with `ENABLE_USER_SCRIPT_SANDBOXING` a run script can't delete it ("Operation not permitted"). Debug-only resources need their own home, or the sandbox off for that one target. **What worked (20 October 2026):** take the files out of the package target, keep one copy in a test-only target's resources (the package tests read it there), and list the same folder as a folder reference in the app target's own Resources phase, with `EXCLUDED_SOURCE_FILE_NAMES = <folder name>` in `Release.xcconfig`. The exclusion does work on the app target's own phase (the sandbox stays on). The package code finds the folder at run time in the app bundle, then next to the test bundle (`NookKit_<Target>.bundle`), and falls back to a missing path. Then make the Release check inspect the built `.app` (the folder name, the resource bundle names, and any file named like a sample photo), and prove it with a planted file and with the exclusion switched off. Cut 12.6 MB from the Release `.app`. (Nifty Outfit Nook, release cleanup)
- **Timestamp build numbers in an ignored xcconfig need no commits.** `CURRENT_PROJECT_VERSION = 20261016.1420` (UTC date, then time without a leading zero) in a git-ignored file included with `#include?` always goes up, on any Mac. Set `manageAppVersionAndBuildNumber` to false in the export options so the app matches App Store Connect. (Phase 18)
- **Mark sample-data uploads TestFlight Internal Only** (Organizer, or `testFlightInternalTestingOnly` in the export options). Such a build can never reach external testers or the App Store. Internal testers must be App Store Connect users with Account Holder, Admin, App Manager, Developer or Marketing; Marketing limited to the one app is the least access. Internal builds need no review. (Phase 18)
- **Set the launch screen's colour with a tiny Info.plist next to the generated one.** `INFOPLIST_FILE` pointing outside the synchronized folder, holding only `UILaunchScreen` > `UIColorName`, merges with `GENERATE_INFOPLIST_FILE`; drop `INFOPLIST_KEY_UILaunchScreen_Generation`. (Phase 18)

## 15. Backend and gateway

Checked on 21 October 2026 with Xcode 27.1 (Swift 6.4), the iOS 26.5 simulator, Node 26.3, `convex` 1.47.0 and `convex-test` 0.0.63.

**Do this**
- Write the API as one versioned contract file with golden JSON examples, and test both the backend and the app's `Codable` types against the same files. Keep a byte-identical copy in the app repo with a hash manifest, so a hand edit fails a test.
- Build the app's client against an in-process fake backend behind a `URLProtocol`, made from the same contract types, with a mode for every failure: slow, timeout, expired token, 403, 429 with Retry-After, 5xx, malformed JSON and offline.
- Put the real sign-in SDK behind a protocol, and switch to it only when its key and the backend URL are both set in an ignored config file. Commit a template.
- Test the backend's token checks against a real local backend with a fake issuer, not only with a mocked identity.

**Convex**
- **A local Convex backend runs without an account.** `CONVEX_AGENT_MODE=anonymous npx convex dev` downloads Convex's backend binary from its GitHub releases into `~/.cache/convex`, keeps data in `.convex/` (git-ignore it) and serves `127.0.0.1:3210`, with HTTP actions on `:3211`. `npx convex dev --once` stops the backend when it's done, and stopping the CLI leaves the `convex-local-backend` process running, so a test script has to kill it. (Phase 24a)
- **Convex refuses to push an auth config that reads an unset environment variable** ("Environment variable X is used in auth config file but its value was not set"), even inside an `if`. So an optional test-only provider can't hide behind an env var. Instead, point the one real provider at a local fake issuer: a small Node server serving `/.well-known/openid-configuration` and a JWKS on `http://127.0.0.1`, minting RS256 tokens. The local backend accepted the `http` domain and then refused expired, wrong-audience, wrong-issuer and wrongly signed tokens with the real config. (Phase 24a)
- **Convex's error for a refused token doesn't say why.** An expired token and a bad signature both just fail `getUserIdentity()`. To tell the app "expired, refresh" apart from "invalid", read the token's unverified `exp` after Convex has refused it; it only picks the 401 code. (Phase 24a)
- **The caller's identity carries from an HTTP action into `ctx.runQuery` and `ctx.runMutation`**, on the local backend and in `convex-test`, so internal functions can take the user from `ctx.auth` instead of an argument. (Phase 24a)
- **`convex-test` runs on Node's built-in test runner, without Vitest,** when you pass the modules map yourself (paths ending in `/convex/...`, including `_generated`). Node 24 or later runs the TypeScript directly, but relative imports need explicit `.ts` or `.js` extensions, which Convex's bundler also accepts. (Phase 24a)
- **An internal function called over Convex's client protocol** (`POST /api/query`) answers HTTP 200 with `{"status":"error"}` and "Could not find public function". Check the body, not the status. (Phase 24a)
- **Test account deletion with a step failing part-way, on the real runtime.** A purge that deletes the principal row before the sign-in provider's user is gone leaves a window where `POST /v1/session` sees "no account" and makes a new one. `convex-test` passed; the local-backend test with the Clerk mock failing (switched with `npx convex env set`) found it. While a deletion runs, every endpoint, sign-in included, should answer by the deletion record, not the principal. (Phase 24c)
- **Scheduled retries in `convex-test` sit on real timers.** A failure that schedules a retry 30 seconds out keeps the test process alive and runs after the test ends. Turn on Node's fake timers (`mock.timers.enable({ apis: ["setTimeout"] })`) before the backend schedules anything, run them with `t.finishAllScheduledFunctions(() => mock.timers.runAll())`, and `mock.timers.reset()` after each test. (Phase 24c)
- **A list of every table in the deletion test** (deleted, never names an account, or kept on purpose) fails as soon as someone adds a table without deciding how deletion treats it. Read the table names from `schema.tables`. (Phase 24c)

**The iOS side**
- **A `URLProtocol` that never answers is ended by `URLSession`'s own timeout** (`timeoutIntervalForRequest`), as `URLError.timedOut`, so a fake timeout mode needs no timer of its own. A test with a 0.5-second timeout and two tries finished in about a second. (Phase 24a)
- **xcconfig files treat `//` as a comment**, so a URL needs `https:/$()/host`. A custom Info.plist key `$(SETTING)` then expands to the full URL; checked in the built app's Info.plist. (Phase 24a)
- **SwiftPM resolves every package a dependency declares, even for products you don't use, but builds only what you link.** Adding `clerk-ios` for `ClerkKit` put Nuke and PhoneNumberKit (used only by `ClerkKitUI`) into `Package.resolved`, but neither was built or in the app. Its test-only packages weren't resolved. (Phase 24a)
- **Check an auth SDK's Keychain class and telemetry before shipping it.** `clerk-ios` 1.6.1 stores its session with `AfterFirstUnlockThisDeviceOnly`, fixed in `SystemKeychain.swift`, and sends telemetry unless `telemetryEnabled: false`. (Phase 24a)
- **gitleaks flags made-up keys in tests.** Literal `pk_test_...` and `sk_live_...` values tripped `generic-api-key` and `stripe-access-token` in the pre-commit hook. Assemble them at run time (`"pk_" + "test_" + String(repeating: "x", count: 24)`). (Phase 24a)
- **`URLRequest.timeoutInterval` only limits silence.** A server that sends one byte every 100 ms kept a 300 ms request alive for almost 10 seconds, and only the byte-by-byte fake showed it (a plain slow answer is caught by the idle timeout too). A hard limit per try is the request racing a `Task.sleep` in a `withThrowingTaskGroup`, cancelling the loser. It also stops when the calling task is cancelled, and nothing is left running. (Phase 26)
- **Retry only what may have reached the server and is safe to repeat.** A timeout and `URLError.networkConnectionLost` mean the request may have been processed; `notConnectedToInternet` means nothing was sent. Retrying the first two for requests that carry an Idempotency-Key, and failing at once on the third, is what the fake backend's "does the work, then the connection drops" mode checks: the retry gets the first answer back and the job runs once. (Phase 26)
- **A 409 "still running" is a poll, not a failed try.** Asking again with the same key until a deadline, instead of spending the three tries on it, lets a long job finish without hammering the server. A deadline check before every wait stops a backoff from starting that can't finish. (Phase 26)
- **Make the connection monitor a hint.** `NWPathMonitor` can lag behind a connection that just came back, so the offline banner reads it but the request is still sent. `URLSession` with `waitsForConnectivity` off fails at once when there really is none. Nothing is queued while offline: a queued paid request could run hours later. (Phase 26)
- **Swift 6.4 details found on the way.** `@Entry` refuses a class as its default value ("reallocated on every access"): point it at a `static let`. A `do` inside a `Task` closure needs `do throws(MyError)` to keep a typed `catch`; without it `error` is `any Error`. In XCUITest an `accessibilityIdentifier` set on a container is copied to every child, so look the banner up by `staticTexts[id]`. `swift build --target Networking` on the Mac failed while compiling Models (target macOS 12.0), so package tests go through `xcodebuild` on a simulator. (Phase 26)

- **A protocol requirement and a test double can merge into a broken branch with both PRs green** (Nifty Outfit Nook, 21 October 2026). Phase 24c added a requirement to `AuthProvider`; Phase 26, branched earlier, added two test doubles without it. Each PR passed CI on its own; together `develop`'s test target didn't compile. Merge the base branch in and build the test target before merging, or require branches to be up to date.
- **Keep the AI provider behind the server from the first call.** The app sends a provider-neutral request with the consent text's version; the server picks the model from configuration and sends only to a recipient that version covers. A model change or a backup provider is then a server change, and a new recipient can't slip past the consent she gave (Phase 27a).
- **Prompt caching wants stable bytes, so send aliases, not IDs.** Order the prompt as fixed policy, then the user's catalog, then the request, with a cache breakpoint after each of the first two, and replace record IDs with short aliases by sorted order so the catalog block is byte-identical between requests (and cheaper). Check the model's minimum cacheable length: 512 tokens on the 2026 Haiku, 4,096 on the one before (Phase 27a).
- **`.map(SomeID.init)` crashed the Swift 6.4 type checker** ("failed to produce diagnostic") when the type also has `init(from:)`. Write the closure, `.map { SomeID($0) }`.
- **Support notes need no App Attest, and a screenshot has to be cleaned twice** (24d, Nifty Outfit Nook, 22 October 2026). A free endpoint that must work on a device that can't attest is protected by the token, per-account and all-account limits and size caps; put the limits before the file is stored, and make a resend with a random note ID return the same ticket. Strip metadata on the phone (re-encode from pixels) and again on the server from the file's structure (JPEG: keep decode tables, frame, scan and the colour profile, drop every other APPn segment, comments and trailing bytes; PNG: keep image and colour chunks), without decoding anything, so a crafted image costs nothing.
- **Audit metadata by field, not by dictionary.** ImageIO writes a minimal `{Exif}`, `{TIFF}` and `{JFIF}` into every JPEG it makes (size, colour space, resolution), so "has an Exif dictionary" is true of a clean picture. Flag GPS, IPTC and any Exif, TIFF or PNG field outside a short technical list.
- **Node's `mock.timers.enable({ apis: ["Date"] })` threw on Node 24** (`isMock` of undefined); `mock.method(Date, "now", () => clock)` plus a `tick()` is a working injected clock for `convex-test`. In a Swift test struct a `Mutex` stored property fails ("non-Copyable"): wrap it in a small `final class`.
- **A URLProtocol that reads the request body into memory needs its cap raised with the largest endpoint,** or the one big endpoint gets a truncated body and a confusing error.
