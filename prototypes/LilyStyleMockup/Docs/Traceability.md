# Screen and flow traceability

This maps each destination in the mockup prompt to the PRD v2 sections it implements, where the code lives, and what is real, simulated, conditional or deferred. Requirement IDs refer to [My_Petite_Style_PRD_v2.md](../../../My_Petite_Style_PRD_v2.md). "Native check" points at the evidence in [Verification.md](Verification.md).

Status meanings:

- **Prototype**: works locally in the app with fictional data through the real store rules.
- **Simulated**: the screen and states work, but the external service behind them is a mock (stylist, images, search, ranking, weather, photo descriptions, StoreKit, iCloud, export, feedback backend).
- **Conditional**: the PRD gates the real feature behind evidence (TO-01–08, RV-28/29, §24.5). The prototype only demonstrates the intended UX, labeled as simulation.
- **Deferred**: not in this prototype; a production or follow-up task.

Body size and fit inputs (confirmed waist, hip and bust first, weight only as a labeled rough fallback) follow an owner decision that goes further than the current PRD text. Rows that depend on it cite "body-size proposal", which points at [PRD-amendment-body-size.md](PRD-amendment-body-size.md). The master PRD itself hasn't been changed.

## Deferred or outside this prototype

- Real providers: text stylist, Apple Foundation Models routing, image rendering, web search, fit ranking, photo understanding, WeatherKit.
- Production persistence (SwiftData/CloudKit), migrations, real export archives, iCloud sync and conflict resolution, StoreKit 2 billing, App Attest, backend gateway and cost ledger.
- Real local notifications for purchase reminders (the in-app reminder records exist).
- The Wardrobe "select items → collage/share" multi-select path in Closet (Ask another stylist covers single garments and looks).
- Pixel-based or semantic image search (§11.9 says first release is metadata search only).
- Several kept editor drafts (one per origin). The prototype keeps one draft and asks before replacing it.
- Multiple iPad windows. The app runs as a single window (`Config/Info.plist`), because every window would share one navigation model. Split View, Slide Over and Stage Manager resizing still work.
